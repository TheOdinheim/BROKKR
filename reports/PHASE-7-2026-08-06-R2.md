## 2. The two Step-0 readings the prompt required — resolved

**(a) `AuthorizedAction` cannot be held by an `AuditEvent`; the authorization event records the `Action`
+ the decision.** `AuthorizedAction` has no public constructor and derives neither `Clone` nor `Copy`
(I-1), so it cannot be stored or copied. `AuditEvent::Authorization` therefore carries
`AuthorizationRecord { action: Action, outcome: AuthorizationOutcome }` — the `Action` (which *is* `Clone`,
obtained in practice via `AuthorizedAction::action()`) plus `Granted | Anergy { reason: AnergyReason }`.
SAGA records the token's **shadow**, not the token; I-1 is untouched.

**(b) `RiskRegister::record(&self, ..)` ⇒ interior mutability; `brokkr-audit` is a `std` crate.** The
trait takes `&self`, so the store sits behind a `Mutex`; `brokkr-audit` is `std` exactly as `brokkr-barrier`
is. The lock is acquired **without panicking** on a poisoned guard (`lock().unwrap_or_else(|p| p.into_inner())`),
honoring the §6 no-`unwrap` discipline. §6.9 line 1033 names this as an implementation consequence, not a
new requirement.

## 4. Task 4(ii) — re-signing cannot resurrect erased data, **structurally** (not merely intended)

The re-signer (`Saga::resign`) receives only a `&DualKeyPair`, whose surface is `sign_dual` / `verify_dual`
/ `public_key_bytes` — **no decrypt method**. The `Saga` struct holds **no** `brokkr_crypto::SubjectKey`
and no field offering decryption. `resign` operates over `record_signed_content`, which copies any
`ciphertext: Vec<u8>` **verbatim** into the digest input and never decrypts. The only type in the codebase
that can turn ciphertext into plaintext is `SubjectKey::unwrap_data_key`, and `SubjectKey` **never appears
in `brokkr-audit`** (confirmed by grep: `brokkr-audit/src` contains no `SubjectKey`). So a decrypt path is
**unrepresentable**, not merely un-taken — the same structural device as `AuthorizedAction`, pointed at the
erasure guarantee. Erasure (`SubjectKey::shred`) is the crypto layer's, invoked by the caller who holds the
key outside SAGA; SAGA only records the tombstone. This division is exactly why the guarantee holds:
because SAGA never holds the key, re-signing an erased record structurally cannot restore it. Proven live by
`test_oqgf_p_11_7_resigned_erased_record_stays_irrecoverable`.

## 5. The Rev 1.10 property, executable, and the A.6.1 Signal choice

- **`test_oqgf_a_6_resigning_does_not_break_the_chain`** appends three records, re-signs record 0 under a
  new generation, then asserts the whole chain still verifies **and** records 1 and 2 have byte-identical
  `prev` values. This is the Rev 1.10 correction, run rather than assumed.
- **`test_oqgf_a_6_resigning_preserves_original_signature`** asserts the original `GenerationSignature`
  (generation 1) is still present and first after a re-sign appends generation 2, and both verify.
- **Chain-break Signal (Task 3): `SignalClass::ThreatDetected`, `Severity::Critical`, from `OrganId::Audit`,
  `PostureEffect::Raise` (raise-only).** A hash-chain mismatch means the append-only record — the ground
  truth every other organ reasons from (KVASIR's seeds, EIR's preservation) — can no longer be trusted;
  that is a detection of a concrete integrity failure (`ThreatDetected`, not `StateChangeNotice`), at the
  highest severity SAGA can raise (`Critical`). The Signal is **constructed and signed**, not merely
  returned as an error (`test_chain_break_emits_a_6_1_signal`).
