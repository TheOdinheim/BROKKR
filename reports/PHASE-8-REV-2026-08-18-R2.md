## The EIR trait drop (labeled decision — for DAP review)

`impl ResolutionEngine for Eir` is **removed**; `may_resolve`, `resolve`, `scan_chronic` are now
**inherent** methods on `Eir` taking `now`. Why, stated plainly:

- The committed `ResolutionEngine` trait carries no `now`, and cannot gain one without a
  `brokkr-core` change that also breaks core's own `MockResolutionEngine` (out of scope).
- Deleting EIR's `now` field (Task 3) while keeping the trait methods is impossible — a trait
  method with no `now` parameter and no held clock has no time source.
- Therefore the only in-scope way to satisfy "delete the field" + "methods take `now` per call" is
  inherent methods. Architecture §6.7 already establishes inherent `now`-taking methods (`observe`)
  as the pattern; this extends it to EIR.

**If the DAP intended EIR to retain the `ResolutionEngine` trait, this decision should be reverted
in favour of the GAP-002 path** — a `brokkr-core` trait revision adding `now` to `ResolutionEngine`
(and `ToleranceController::grant_heuristic`) placed first, then this revision consuming it. I chose
the in-scope inherent-method realization because the prompt is explicit (sentinel-only, delete the
field, methods take `now`) and the test specs require it; the trait remains available in core and
nothing else implements-or-calls it against `Eir`.

## Task 1 — the evaluation loop (§6.7)

`Heimdall::observe(&self, o: &Observation, now: Timestamp) -> Vec<Detection>` (inherent). Every
registered detector observes every observation; a firing is checked against **live** grants; a
suppressed firing is **recorded** (`suppressed_by: Some(id)`, no Signal) and an unsuppressed one
carries a **raise-only** Signal. Cross-hop reconciliation **joins** the loop as one more firing
(reserved detector id `cross-hop-reconciliation`), subject to the same suppression — it is no longer
a side path. **`Detection` fields derived from §6.7's placed text:** `detector, severity, detail,
suppressed_by: Option<GrantId>, signal: Option<Signal>`.

**`reconcile` decision (reported):** the former **public** `reconcile` method is **removed**; its
logic is a private free function `reconciliation_deviation(o) -> Option<&str>` consumed inside
`observe`, and the two tests that called `reconcile` now call `observe`. Reconciliation is inside
the loop, not beside it.

**A suppressed firing is still returned** — discarding it would make a grant indistinguishable from
a detector that was never registered (§6.7).

**CONFIRMED — no path through `observe` permits an action.** `DetectionVerdict` has exactly
`Clear | Fired` (no permitting variant); `PostureEffect` has only `Raise`; `Detection` carries at
most a raise-only `Signal`. The strongest outcome is a raise. This is I-9's fixed-`Heuristic`
guarantee at the interface.

## Task 2 — retain grants

`HeimdallState.grants: Vec<(GrantId, ToleranceGrant)>`. `grant_heuristic` validates (signature →
scope-non-blank) and **retains** (pushes to `grants`), returning the `GrantId`. **Liveness for a
firing, in §6.7 order** (in `observe`): (1) signature — checked at issuance; (2) scope covers the
firing detector — `grant.target == detector`; (3) `now <= expiry` — the per-call check.

**Live vs spent without deleting (reported):** an expired grant is **not removed** — it stops being
live (the loop's `now <= expiry` fails) and stays in the register, because OQGF-P-9.5's inventory
records decisions *taken*, not decisions in force. Liveness is computed per firing from `now`;
spentness is never a mutation.

## Task 3 — I-13: delete the field, not just the setter

Deleted `set_now` and the `now` **field** from both `HeimdallState` and `EirState`, and the `now`
parameter from both constructors. Time-dependent methods take `now` per call: HEIMDALL — `observe`
(the only HEIMDALL method that reads a time; `grant_heuristic` and `host_harm` read none after the
move); EIR — `may_resolve`, `resolve`, `scan_chronic` (feeding `classify`, which already took `now`
as a parameter and is now fed the call value, not `st.now`).

**CONFIRMED — no held clock in `brokkr-sentinel/src`:** `self\.now`, `\.state().now`, `st\.now`,
`Mutex<Timestamp>`, `fn now(` all **empty**; `EirState`/`HeimdallState` have no `now` field. The
remaining `now: Timestamp` occurrences are all function parameters (the exhaustive table, Task 6,
confirms each comparison's source). The workspace builds green (nothing needed the setters — the
CERTAIN CHECK).

## Task 4 — EIR: expiry before replay (§6.8)

Final order in `resolve`: **signature → expiry → replay → something-to-resolve → readiness.**
Signature is still first (an unauthenticated decision's `nonce`/`expiry` are untrustworthy). Expiry
now precedes replay: a decision reaching a replay-first expiry check must carry an unseen nonce, so
an expired-and-previously-accepted decision was refused as `ReplayedNonce` and the `Expired` arm was
unreachable for exactly that case. Expiry and replay do not overlap in practice, so a decision that
is somehow both reports `Expired`. Proven by the new `test_oqgf_p_8_5_expired_before_replay_reports_
expired`, which **fails against the old order**.
