## 2. What was built

`brokkr-intent` — pure logic, `#![forbid(unsafe_code)]`, the first consumer of
`brokkr-crypto`:

- **`canonical.rs`** — the load-bearing deliverable. A deterministic, unambiguous,
  length-prefixed encoding of the *signed content* of `RootIntent` and `IntentChainEntry`,
  covering `emitted_scope` in full. `BTreeSet` sorted iteration gives determinism; an
  8-byte BE length prefix on every variable field gives unambiguity (no delimiter to
  spoof); each structure carries a domain-separation tag. Hand-written — no serialization
  crate, because serde/bincode/postcard output is not guaranteed canonical.
- **`skuld.rs`** — `Skuld` (realizes the `IntentChain` trait): `sign_root`, `verify_root`,
  `attenuate_signed` (the real `attenuate`), `verify_chain`, and `IntentError`. Real
  dual-family signing, SHA-384 hash-linking, and freshness.

**No new dependency.** Only `brokkr-core` + `brokkr-crypto` (asked-nothing — thiserror was
declined in favor of a hand-rolled `IntentError`, consistent with the zero-dep pattern).

## 3. How M-9 is made real ("infeasible, not merely detectable")

Three layers: (i) in-process, broadening is *unrepresentable* — `brokkr-core`'s `extend` is
the only append and rejects a non-subset scope; (ii) the entry signature commits to the
canonical `emitted_scope`; (iii) each `received_digest` is the SHA-384 of the prior state's
full canonical bytes, so tampering breaks the link. To present a **broadened chain that
verifies**, an attacker must forge a `DualSignature` — an ML-DSA-65 **and** an
SLH-DSA-SHAKE-192s forgery. That is the M-9 bar. The isolating proof is
`test_oqgf_m_9_scope_tamper_within_subset_fails_signature`: a tampered scope that still
satisfies the subset check and preserves the hash link **still fails**, on the signature.

**The serialized-adversary model:** `verify_chain` operates on the *reconstructed* parts
(`&RootIntent`, `&[IntentChainEntry]`) — which never passed through `extend`, so it
independently re-checks the subset at every hop (the type guarantee did not travel with the
bytes), plus every signature and every hash link.

## 4. Freshness (M-14)

Enforced *here* (core declares `AttenuationError::Expired` but never returns it). `now` is
an explicit parameter — never a wall-clock read — so the negative test is deterministic.
Checked in both `attenuate_signed` (an expired chain authorizes no new hop) and at the
*start* of `verify_chain`, before the walk (AMD.5.3 step 2).
