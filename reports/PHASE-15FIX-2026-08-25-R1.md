## 1. The fixes

### F-22 / F-26 (LOW) — uniform denial reason under production guards
`brokkr-cli::execute_hop`: a new `pub const UNIFORM_DENIAL_REASON = "action denied"`. Under `uniform_denial_stage` (production), **both** the genome-refusal path and the SINDRI-anergy path return `UNIFORM_DENIAL_REASON` — so the returned `(stage, reason)` pair is identical whether a tool is undeclared or declared-but-denied. The genome-enumeration oracle (13-FIX F-5 closed on the stage; 15A F-22 re-opened on the reason; 15B F-26 showed it enumerates the whole genome with perfect accuracy) is now closed on both channels. **SAGA is unchanged:** `record_authorization` still writes the attempted `action.tool` and the specific `AnergyReason`, so the trusted audit keeps the truth; only the caller-facing string is uniformed. Under permissive guards the specific reason (and the true `Genome`/`Gate` stage) is still returned, so the spine-verifying rigs keep probing.
**Regression:** `redteam_15fix::fix_f22_uniform_reason_string_under_production` — an undeclared tool and an out-of-scope tool return the identical `(Gate, "action denied")`; fails without the fix (reasons were "tool X not declared" vs "architectural anergy: OutOfScope").

### F-29 (LOW) — nonce-cap eviction restricted to expired entries
`brokkr-cli::check_guards`: the F-13 cap previously evicted the smallest-expiry entry at capacity, which could evict a still-*fresh* target nonce and open a replay window (15C F-29). The fix: since the `retain(now <= expiry)` at the top of the replay block already drops every expired entry, a ledger still at `MAX_NONCE_ENTRIES` holds only valid nonces — so rather than evict a fresh one, **reject the new chain** with `"nonce ledger full — too many active chains"`. A fresh nonce is therefore never evicted and never replayable. The memory bound is preserved (the ledger never exceeds the cap); the tradeoff is availability under a genuine 10⁴-fresh-nonce flood, which is an adversarial signal, not legitimate load.
**Regression:** `redteam_15c::g2_2_4_nonce_flood_no_longer_opens_a_replay_window` (updated from `..._opens_a_replay_window`) — after flooding `MAX_NONCE_ENTRIES` fresh nonces, the overflow is rejected ("ledger full") and replaying the target is still denied. Fails without the fix (pre-fix there is no "ledger full" path and the target is evicted → replay admitted).
