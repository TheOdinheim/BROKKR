## 2. What changed

- **`resolver.rs`** — added the `GenomeResolver` seam and its two projection types `ResolvedTool { required_capabilities, privilege }` and `ResolvedInvariant { forbids_capabilities, forbids_privilege }`. Projections, not the full `ToolEntry`/`InvariantEntry`: the gate evaluates exactly these fields and reads nothing else the genome holds. `brokkr-gate` gains **no** `brokkr-genome` dependency — the seam keeps the projection at the gate boundary (production backs it from the genome).
- **`Sindri`** — now `Sindri<R: KeyResolver, G: GenomeResolver>` holding both resolvers; `new(resolver, genome_resolver)`; both `impl` bounds updated. The `CostimulationGate` **trait** is unchanged; only the implementing struct gains a generic. `authorize` (the provided minter) is untouched.
- **`evaluate`** — `_action` → `action`; conjuncts 3 and 4 added after `signal_2`, before `Ok(())`, in the flowchart order Signal 1 → Signal 2 → Conjunct 3 → Conjunct 4.
  - **Conjunct 3:** `resolve_tool(&action.tool)` — `None` ⇒ `OutOfScope` (an undeclared tool is a denied tool); then every `required_capabilities` entry must be in `chain.current_scope()`, else `OutOfScope`. Empty requirements are vacuously satisfied.
  - **Conjunct 4:** for each accumulated invariant, `resolve_invariant(inv)` — `None` ⇒ `InvariantViolated` (fail-closed: an invariant with no declared predicate denies); then `InvariantViolated` if the tool requires any forbidden capability or carries a forbidden privilege class. No invariants ⇒ nothing to violate.
- **`lib.rs`** — re-exported `GenomeResolver`, `ResolvedTool`, `ResolvedInvariant`; the "What Phase 4 enforces" doc that called conjuncts 3/4 *deferred* and `OutOfScope`/`InvariantViolated` *unreachable* was corrected — those statements are now false, and all four conjuncts are described as enforced.

**No `brokkr-core` type changes; no new crates; `authorize` unmodified.** New code carries no OQGF section numbers, amendment refs, or "SHALL" in comments; the now-false "deferred/unreachable" doc lines were corrected in plain language.

## 5. Deadline and the named residual

The Deferred-Conjunct Deadline (§6.4) is: *the executor SHALL NOT be wired to a gate that does not evaluate the action against the chain's current scope and accumulated invariant set.* `evaluate` now does both — conjunct 3 against the current scope, conjunct 4 against the accumulated invariant set. **The structural half is built; the RISK-2026-0004 disposition is the DAP's to update after verification** (not touched here).

**The detail-level-invariant residual (§13) is unchanged and out of scope.** Conjunct 4 evaluates the *declarative* invariant predicates (`forbids_capabilities`, `forbids_privilege`), which are computable from the genome. Invariants that require interpreting `Action.detail` (a path rule like *read-only outside ./src*) are still not evaluated — that is the named §13 residual, and this revision neither closes it nor claims to.
