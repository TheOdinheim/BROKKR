## 2. The three Step-0 readings the prompt required, resolved and reported

- **`AcceptedRisk { entry: RiskAcceptanceId }` entry id — not invented.** `RiskAcceptance` carries no
  `id`, but OQGF-P-9.2 requires entries "recorded in Organ 5," and a register record has a key. So the
  **acceptance resolver returns `(RiskAcceptanceId, RiskAcceptance)`** — the id is the register's key,
  supplied by the resolver/Organ-5 seam; the Barrier copies it into `AcceptedRisk`, never synthesizing
  it. Concluded **buildable, non-inventing** (the defensible reading the prompt endorsed).
- **Multiple failing conditions — first-failing in §6.5 order.** The egress gate evaluates conditions
  2→9 in order and the finding names the **first** to fail. This is deterministic and matches the order
  a DAP reasons about; and it is load-bearing, because the acceptance a DAP wrote must match the
  finding actually raised (the finding's `finding_id` is `(datum, condition)`).
- **Acceptance on Quarantine — does not apply.** A `Quarantine { datum }` carries **no**
  `BarrierFinding` (no `finding_id` to scope an acceptance to) and is **not a `Deny`**; OQGF-I-11's
  remedy for quarantine is *establishing provenance*, not accepting a risk. So only the egress `Deny`
  consults the acceptance resolver. Reported, not silently allowed.

## 3. What was built

- **`canonical.rs`** — signed-content encodings for the BCR and the RiskAcceptance, domain-separated
  (`brokkr-barrier:bcr:v1`, `brokkr-barrier:risk-acceptance:v1`), length-prefixed, exhaustive enum tags
  (no catch-all), signature excluded.
- **`resolver.rs`** — the two injected seams: `EndpointCeiling` (Task 5) and `AcceptanceResolver`
  (Task 6, returning the `(RiskAcceptanceId, RiskAcceptance)` pair), each with an in-memory impl.
- **`huth.rs`** — `Huth<C, A>: Barrier`. Egress (conditions 1–9, first-failing finding, honor-or-deny);
  ingress (provenance/quarantine/privileged-personal); the honoring rule (finding-id match, `gate ==
  Some(Barrier)`, dual-family signature under the DAP key, `now ≤ expiry`).
- **`uncontrolled.rs`** — `UncontrolledChannelRegister` (OQGF-I-14), which **enforces nothing**.

**Keys held as bytes.** The Barrier stores the BCR and DAP verifying keys as raw dual-family public
**bytes** and mints a `DualPublicKey` per verification (fail-closed on a malformed key) — the same
pattern SINDRI's `RegistryResolver` uses, and it keeps `Huth` `Send + Sync` (the `Barrier` trait
requires it). Neither key is read from the artifact it verifies (non-circular).

## 4. Condition 8 and the endpoint-ceiling seam (Task 5)

`LocalPath` has no channel (condition 8 n/a). `Network`'s ceiling is `channel.permits()`. `Reasoner`'s
is `effective_authorization(resolved_endpoint_max, ChannelStrength::from_group(negotiated))`. **An
unresolvable endpoint fails closed as `ChannelStrengthCollapse`** — without the ceiling the Barrier
cannot prove the channel may carry the data, so it denies on the channel-strength axis (the natural,
fail-safe condition; the alternative — inventing a default ceiling — would be a silent relaxation).
`brokkr-barrier` does **not** depend on `brokkr-genome`; REGIN supplies an `EndpointCeiling` impl.
