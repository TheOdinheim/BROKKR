## 1. What was built

`brokkr-genome` provides two things and no I/O:

- **Canonical serialization** (`canonical.rs`) — deterministic, length-prefixed, domain-separated
  signed-content encodings for all six registers and the genome.
- **The promotion gate** (`gate.rs`) — `promote(genome, dap_key, now) -> PromotionVerdict`, a
  fail-closed Deterministic Gate evaluating the six §6.2 Rev 1.5 predicates, returning `Promoted` or
  `Blocked` with every typed `Finding`.

## 3. The four required design determinations (re-verified against source, not re-derived from R1)

- **Verdict-type placement → `brokkr-genome`.** No core trait returns a promotion verdict (unlike
  `Barrier`→`BarrierVerdict`); `genome.rs` declares no gate trait. `PromotionVerdict` is produced by
  REGIN and consumed by the release pipeline (Phase 11) — a genome-crate concern, not cross-cutting
  core vocabulary. Placing it in core would be a separate core revision; it is not. The I-2
  no-downgrade discipline is encoded here (it does not require core residence). Re-verified: `Barrier`
  trait in barrier.rs returns `BarrierVerdict`; no analogous promotion trait in core.
- **Self-Set screening (OQGF-P-3) — excluded.** §5.1's Phase-5 scope line does not list it; `SelfSet`
  (tolerance.rs) is HEIMDALL's, screening detectors that do not exist until Phases 8–9. Not built.
- **Genome signature covers register signatures — implemented.** `canonical::genome_signed_content`
  covers `version`, `corpus_digest`, `owner`, and each register's **full** bytes *including* that
  register's signature. So the genome signature commits to which signed registers it was assembled
  from — swapping in a differently-signed register breaks the genome signature (shown by
  `test_oqgf_g_4_tampered_register_fails_signature`, which produces both the register finding and,
  because the genome content changed, the genome finding).
- **Non-suppressibility — structural, verified.** A `ToleranceGrant` targets a `DetectorId`; the gate
  has none. Verified by grep: `DetectorId`/`ToleranceGrant` appear only in doc comments, never in
  code — the gate exposes no tolerance surface, so there is no value a suppression could point at.
  This is *why* it is non-suppressible, stated as a verified fact.

## 4. Canonical serialization — the load-bearing deliverable (Task 1)

Follows `brokkr-intent/src/canonical.rs`'s discipline exactly: an 8-byte BE length prefix on every
variable-length field, a 1-byte tag for enums, no delimiters. Each register's signed content begins
with its **own domain tag** (`brokkr-genome:tools:v1` … `:genome:v1`), so a signature over one
register cannot verify against another — the highest-risk property, tested directly
(`test_domain_separation_across_registers`: byte-inequality **and** cross-register signature
non-verification). Every enum tag function matches exhaustively with **no catch-all arm**, so a new
`SignatureAlg`/`AlgorithmId`/`Classification`/… variant forces a compile error rather than a silent
colliding tag. Hand-written; no serialization crate.

## 5. Signature verification — non-circular (Task 2)

`promote` takes `dap_key: &DualPublicKey` as an **explicit parameter** — the genome owner's verifying
key, supplied out of band. It is **never** read from the genome's own `RootsOfTrust` register (which
is itself signed; verifying it with a key it contains would prove nothing). Every register's
`DualSignature` and the genome's are verified via `verify_dual` (both ML-DSA and SLH-DSA required),
fail-closed. `test_wrong_dap_key_blocks_all_signatures` proves the non-circularity: a valid genome
verified with a different key fails every signature.

## 6. The verdict and the gate (Tasks 3, 4)

`PromotionVerdict` mirrors `BarrierVerdict`: two states (`Promoted` | `Blocked { findings }`), typed
`Finding`s (one variant per failed predicate, carrying which register/endpoint/tool/invariant), no
`AcceptedRisk` and no placeholder variant, and **no conversion from `Blocked` to `Promoted`** (proven
by the `compile_fail,E0599` doctest, mirroring `BarrierVerdict`'s). The gate evaluates **all six
predicates and returns all findings** (`test_all_findings_returned`). Predicate 1 is a type-level
guarantee (I-10) — no runtime check that cannot fail. Predicate 4's staleness saturates
(`saturating_sub`, no panic) and fails a future `reviewed`. Predicate 6 implements the Rev 1.5
narrowing: forbidding a recognized-but-unrequired capability **promotes**
(`test_invariant_forbidding_undeclared_but_known_capability_promotes`); only an out-of-vocabulary
capability or a forbids-nothing invariant fails.
