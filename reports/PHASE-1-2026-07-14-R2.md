## 1. What this revision changed, and why

DAP review accepted the invariant *encodings* and found two proof gaps — both the
Section 5.3 "a test must fail for the RIGHT reason, or it is not a proof" failure,
applied to the compile-fail tests. No new type was built. Nothing was relaxed; this
adds rigor.

### 1a. Every compile-fail doctest now pins its error code

A bare ` ```compile_fail ` passes if the code fails to compile for *any* reason. Each is
now ` ```compile_fail,<CODE> `, so `rustdoc` fails the test unless the compiler emits
that exact code:

| Doctest | Inv | Code | Why |
|---|---|---|---|
| `AuthorizedAction` literal | I-1 | E0616 | private field |
| `AuthorizedAction::mint` | I-1 | E0624 | private method |
| `AuthorizedAction.clone()` (new) | I-1 | E0599 | not `Clone` |
| `BarrierVerdict.into_allow()` | I-2 | E0599 | no such method |
| `EscalationType` `None` baseline | I-8 | E0308 | type mismatch |
| `ResolutionDecision` `None` dap | I-8 | E0308 | type mismatch |
| `ModelEndpoint` `None` client_cert | I-11 | E0308 | type mismatch |
| `Genome` `None` signature | I-10 | E0308 | type mismatch |
| `ClearedContext` literal | I-12 | E0616 | private field |
| `propose(&raw_context)` | I-12 | E0308 | type mismatch |

**Result: all ten still pass with the codes pinned.** Per the prompt, if any had then
failed it would mean it was previously passing for the wrong reason — I would have
reported the real error before fixing. **None failed.** The four `E0308` cases (the ones
using the `any::<T>()` helper, most at risk of an unrelated inference error) confirm the
`None` mismatch is the first and only error rustc reports.

### 1b. The I-1 gap, closed

The old I-1 doctests proved you cannot *construct* or *mint* an `AuthorizedAction`
externally. They did not prove *no `pub fn` returns one except through `authorize`*.
Now closed:

**Source audit of `gate.rs` (grep-verifiable):**

- **`pub fn`s returning `AuthorizedAction` by value: none.**
  `grep -nE 'fn [a-z_]+\(.*\).*AuthorizedAction' brokkr-core/src/gate.rs` → empty. The
  type appears in return position only as `AuthorizationDecision::Granted(AuthorizedAction::mint(action))` (line 125).
- **Sole minter:** `fn mint` (line 82) — **private**, returns `Self`.
- **`mint`'s sole call site:** line 125, inside the provided `authorize`. (Confirmed by
  `grep -nE 'fn mint|AuthorizedAction::mint'`: definition at 82, one call at 125.)
- So the only value-producing path is `authorize` → `mint`. An implementor that
  overrides `authorize` still cannot reach the private `mint`, so it can only ever
  return `Anergy` — fail-safe.

**Clone/Copy:** `AuthorizedAction` derives **nothing** (no `#[derive]` precedes the
struct). It is not `Clone`/`Copy`, so a granted authorization is a move-only capability
and cannot be duplicated outside the gate. There was no derive to remove; the absence is
intentional and is now proven by the new `compile_fail,E0599` `.clone()` doctest.

**New runtime test:** `test_i1_authorize_is_sole_construction_path` obtains an
`AuthorizedAction` via `authorize`, reads it, and confirms a denying gate yields
`Anergy` with no `AuthorizedAction`.
