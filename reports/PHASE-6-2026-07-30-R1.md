## 3. Why the build stopped (detail in `GAP-2026-07-30-001`)

To return `AcceptedRisk` **instead of** a `Deny` (§6.5: the only sanctioned way past a barrier Deny),
the Barrier must decide "this finding is covered by that acceptance." The committed types give it
nothing:

- **No finding identity.** `BarrierFinding` is `{classification, reason: String}` — no id. There is
  **no committed link** from a `BarrierFinding` to a `RiskAcceptance` (whose `finding` is an opaque
  `RiskAcceptanceId`). Matching would require inventing a scheme (hash the reason, synthesize an id,
  or a convention for what `finding` means) — the exact thing Task 6 forbids. A resolver seam does not
  sidestep it: unlike the key/ceiling resolvers (which match on committed `SubjectId`/`ModelEndpointId`
  identities), a risk-acceptance resolver would have no committed identity to match a `BarrierFinding`
  on, so its trait semantics would embed the invention.
- **No barrier gate id.** AMD-007 §AMD.5.1 makes the barrier egress `Deny` a Deterministic-Gate finding
  whose way past is an AMD-006 acceptance. But `RiskAcceptance.gate: Option<DeterministicGateId>` and
  `DeterministicGateId = {Genome, Mhc}` — no barrier variant. `None` means "non-gate risk"
  (misrepresenting a gate finding); neither `Genome` nor `Mhc` is the barrier. The type cannot
  correctly represent a barrier-gate acceptance.

Per §4 both are decisions reserved to the architecture and the DAP. **The whole phase stops** (not
"build 1–5, 7 and gap 6") because Step 0 says report-and-stop before writing, §6.5 places acceptance
in this phase (so its absence is an OQGF-P-9 obligation §5.3 stops on), and building the deny-only core
now would be rework once a finding-identity surface reshapes how the egress gate constructs findings.

## 4. The designs that are ready (so disposition-to-build is fast)

- **Canonical BCR** (Task 1): `Canon` discipline (8-byte BE length prefixes, exhaustive enum tags, no
  catch-all), domain tag `brokkr-barrier:bcr:v1`, signed content excluding `bcr.signature`. Tested by a
  cross-crate domain-separation test (a genome-register signature must not verify as a BCR).
- **Egress gate** (Task 3): conditions 1–9 exactly per §6.5, each `Deny` carrying a
  condition-naming `BarrierFinding`; condition 1 short-circuits only on `Public && personal.is_none()`.
- **Ingress path** (Task 4): provenance-established → Allow; unprovenanced + Privileged → Quarantine;
  unprovenanced + NonPrivileged → Allow; personal + Privileged without a matching BCR tag → Quarantine.
- **Endpoint-ceiling seam** (Task 5): a barrier-owned `EndpointCeiling` resolver trait
  (`ModelEndpointId -> Classification`) injected at construction; `brokkr-barrier` does **not** depend
  on `brokkr-genome` (I-5) — REGIN supplies an impl.
- **Uncontrolled-channel register** (Task 7): a barrier-local enumeration that enforces nothing.

Only the finding→acceptance link and the barrier gate id (Task 6) await the core surface the gap asks
for.
