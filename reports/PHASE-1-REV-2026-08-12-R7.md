## 2. What was placed

- **`resolution.rs` — two new fields (Task 1).** `nonce: Nonce` and `expiry: Timestamp`, in §6.8's field
  order (`escalation, cleared_condition, dap, at, nonce, expiry, signature`); `new` is now 7-argument. Doc
  records **why**: a signature that verifies today verifies forever, so a captured decision could be
  **replayed** later when the escalation it clears is real; resolution is the one act in BROKKR that
  *lowers* a defense, and it was the only signed artifact without freshness (a grant expires, a signal
  carries both, a risk acceptance expires, a BCR expires).
- **`resolution.rs` — the canonical signed content, IN CORE (Task 2).** `resolution_signed_content(&ResolutionDecision)
  -> Vec<u8>` encodes `escalation, cleared_condition, dap(name,id), at, nonce, expiry` — **everything except
  the signature** — under a domain tag, following the sibling discipline exactly (fixed field order, 8-byte
  BE length prefixes, leading domain tag). A minimal private `Canon` (only `u64`/`bytes`, since the signed
  content has **no enums** — all scalars and strings — so no enum-tag functions are needed). Doc records why
  it lives in core: signed by a DAP tool, verified by EIR — two parties, two crates; the bytes are defined
  once where both can see them, the same reasoning as `BarrierFinding::finding_id()`. **Byte composition, not
  a digest** — `alloc::vec::Vec` (already imported), no hasher reached for.
- **`tolerance.rs` — `ToleranceError::SignatureInvalid` (Task 4).** Message *"the tolerance grant's
  signature did not verify (OQGF-P-4)"*. Doc on the enum records that **the controller's checks are ordered
  and it returns the FIRST that failed** (the ordering lives in the sentinel's `grant_heuristic`, not the
  enum): a forged grant reports one true reason, not also a scope verdict never evaluated, which would state
  an unreached finding and hand a forger free information about the shape of a valid grant.
- **`lib.rs` — re-export (Task 5).** `resolution_signed_content` added to the `resolution::{…}` line.

## 3. Task 3 — the doctest trap, handled and verified (not assumed)

The `ResolutionDecision` compile_fail doctest called `new(any(), any(), None, any(), any())` — 5 args. After
Task 1 that arity is wrong, so `compile_fail` would still PASS on an E0061 arity error — green while proving
nothing about I-8. **Fix:** the call is now 7 args with `None` kept in the 3rd (`dap`) slot. **Verified by
compiling the snippet standalone against the built rlib** (not trusting the doctest run, which passes on any
compile error):

- `ResolutionDecision` snippet → **`error[E0308]`** only (expected `Dap`, found `Option<_>`) — **not** E0061.
  The doctest proves I-8's second half again.
- `EscalationType` snippet (I-8 first half, unchanged) → **`error[E0308]`** — unaffected, as expected
  (`EscalationType` was not touched), verified rather than assumed.

The annotations match the emitted codes. This is the third appearance of this trap (Genome::new,
BarrierFinding); treated as expected.

### The workspace breakage — expected, intended, scoped (Task 6)

**The workspace does not build, by design.** Adding the two fields changes `new`'s arity, and exactly one
site outside brokkr-core constructs a `ResolutionDecision`:

- **`brokkr-sentinel/tests/sentinel.rs:197`** (the `signed_decision` helper) →
  **`error[E0061]: this function takes 7 arguments but 5 arguments were supplied`** (pointing at
  `brokkr-core/src/resolution.rs:115`, `new`). This is the **only** compile error in the workspace.

Everything else builds:

- **brokkr-core** — lib + all tests + doctests pass.
- **brokkr-audit** — builds. It *reads* `ResolutionDecision` fields (`event.rs`, `canonical.rs`) and never
  constructs one, so the new arity does not affect it. *(Observation, not a break: `brokkr-audit`'s
  `write_resolution` encodes `escalation/cleared_condition/dap/at/signature` and now omits `nonce/expiry`
  from its audit-record encoding — a minor fidelity gap the audit-side may address later. The full
  `ResolutionDecision` value, including `nonce/expiry`, is still stored in the `AuditEvent`; only audit's
  canonical bytes omit them. Not in scope here, not a compile break, and the resolution audit event is
  placed-and-unexercised until Phase 11.)*
- **brokkr-sentinel lib** — builds. Its `canonical.rs`/`eir.rs` read fields (`d.at`, `d.dap`, …) that all
  still exist; only the **test** constructs a decision.

**The follow-on `brokkr-sentinel` Rev 1.12 revision is therefore a known quantity:** (1) fix the
`signed_decision` helper to the 7-argument `new` (add a `nonce` and an `expiry`); (2) delete the
now-redundant sentinel-local `resolution_signed_content` (tag `brokkr-sentinel:resolution:v1`) and adopt
core's `resolution_signed_content`, so issuer and verifier share one encoding; (3) enforce freshness in EIR
(`resolve` refuses `now > expiry` and a replayed nonce) and return `ToleranceError::SignatureInvalid` for a
forged grant. **I did not touch `brokkr-sentinel`** — that is the next revision.
