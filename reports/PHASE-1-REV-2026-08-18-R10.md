`reasoner.rs`; every implementor and caller of both traits.

**What I-13 forbids, precisely:** a **held** clock — the current time stored as construction
state. It does **not** forbid holding configuration (a bound, a resolver, a verifying key);
those are supposed to be fixed at construction. The current time is the one input that is wrong
the instant after it is read, so it is supplied per evaluating call.

## Task 1 — gate.rs

- `evaluate` and `authorize` each gain `now: Timestamp` as the **last** parameter (§6.4 order).
  `authorize` passes it straight to `self.evaluate(...)` and does nothing else with it. Import
  widened `use crate::ids::ToolId;` → `use crate::ids::{Timestamp, ToolId};`.
- Doc on both states I-13: `now` is a parameter of the evaluating call, never construction state;
  Signal 2's chain check enforces OQGF-M-14 freshness, and a held clock would compare an aging
  expiry against an equally aging present — passing while enforcing nothing.

**CONFIRMED (Task 1):** `mint` remains module-private; `authorize` remains its only caller; an
override of `authorize` still gains nothing — it cannot reach `mint`, so it can only ever return
`Anergy`. **The sealed-minter guarantee (I-1) is untouched by an argument list** — threading a
`Timestamp` through the provided body changes no visibility and adds no construction path. The
gate.rs D3 doctest, updated to the new arity and standalone-compiled, still emits **only** `E0599`
(no `.clone()` on `AuthorizedAction`), confirming no arity error leaked into the I-1 proof.

## Task 3 — the doctest trap, fifth appearance

**First, the trap is real and was empirically confirmed this session.** A probe temporarily
flipped gate D1's annotation to a deliberately-wrong real code (`E0308`) and the doctest **still
passed** — rustdoc's `compile_fail` checks only *that* compilation fails, never *why*. So a wrong
error code is invisible to `cargo test --doc`. Every code below was therefore verified by
**extracting each snippet and compiling it standalone** with `rustc --edition 2024 --extern
brokkr_core=<rlib>` and reading the emitted `error[E....]`.

| Doctest | Declared before | **Actual (standalone)** | Outcome |
|---|---|---|---|
| gate D1 — `AuthorizedAction { action }` literal | `E0616` | **`E0451`** | **annotation corrected → E0451** |
| gate D2 — `mint` (private fn) | `E0624` | `E0624` | matches |
| gate D3 — updated impl + `authorize` + `.clone()` | `E0599` | `E0599` | matches (arity fix left only E0599) |
| gate D-I13 — `authorize` missing `now` (NEW) | `E0061` | `E0061` | matches |
| reasoner D4 — `ClearedContext { inner }` literal | `E0451` | `E0451` | matches |
| reasoner D5 — `propose(&Context)` | `E0308` | `E0308` | matches |
| reasoner D-I13 — `clear` missing `now` (NEW) | `E0061` | `E0061` | matches |

**The one correction — gate D1, `E0616` → `E0451`.** Constructing a struct *literal* with a
private field is **E0451**; `E0616` is private-field *access* (`value.action`). This is the
**identical latent bug Rev 1.14 found and fixed in reasoner.rs** (`ClearedContext { inner }`), and
it has been silently wrong in gate.rs since Phase 1 — rustdoc never enforced it. Corrected here to
the code the compiler actually emits, with a doc note explaining the constructor-vs-access
distinction. The stale `E0616` reference in `negative_invariants.rs` (`test_i1_authorize_is_sole_
construction_path`'s comment) was corrected to `E0451` in the same pass.

**The arity victim — gate D3.** After adding `now`, its impl `fn evaluate(&self, …, _a: &Action)`
would no longer match the 4-arg trait (E0050) and its `authorize(id, ch, a)` call would be short
one argument (E0061), while `compile_fail` stayed green on the *wrong* errors. Updated the impl to
the 4-arg `evaluate` and the call to `authorize(id, ch, a, now)`, so the **only** remaining error
is the intended `E0599`. Standalone compile confirms exactly `E0599`.

**The other half of the trap (runnable / `no_run` doctests).** Audited every fenced block in both
files: **all seven openers are `compile_fail`**; there is no runnable or `no_run` doctest that
calls a changed method, so nothing silently breaks the doc build. (Grep of `^///\s*```` in both
files: only `compile_fail` openers and their closing fences.)

## Task 4 — negative test for I-13

**Reasoning (reported as required).** I-13 is a property of *signatures*, and a test asserting a
held clock is impossible **cannot be written** — an implementor can always store a `Timestamp` in
its own struct, and no core type can forbid that. What **is** provable in core is that all four
methods *require* a `Timestamp` at the call site, so no implementor can be invoked without one
supplied. Two artifacts encode that:

- **`compile_fail,E0061` doctests** on `CostimulationGate` and `ContextClearance` — calling
  `authorize` / `clear` without `now` does not compile. Standalone-verified `E0061` (above).
- **`test_i13_now_is_a_call_site_parameter`** (runtime, name bears the invariant ID per §3) —
  exercises the positive side: `evaluate`, `authorize`, `evaluate_context`, and `clear` all
  accept and are called with `now`.

**Stated plainly, and no more than this is claimed (and it is written into the test body and the
doctest prose):** this proves the **call site supplies the time**. It does **not** prove an
implementor **forwards** `now` to its freshness check rather than ignoring the argument and reading
a stored clock. That residual belongs to per-crate review (SINDRI, BIFRÖST) and the workspace grep
for a held clock — not to core's type system.

**Risk-register determination (Task 7 — reasoned, not assumed).** A risk-register entry **is
warranted**, and I recommend the DAP place it (register mutations follow their own prompt cadence
in this repo, and the scope lock confines this revision to `brokkr-core`, so I do not modify
`risks/` here). Reasoning both ways:

- **Why warranted.** SINDRI held its clock for four phases (Phase 4 → the Phase-8.5 buildability
  check), so OQGF-M-14 freshness was enforced against nothing and the defect *survived a Phase-4
  DAP review*. More importantly, a **residual persists after this fix**: I-13 guarantees the call
  site supplies `now`, but core's type system **cannot** force an implementor to forward it rather
  than hold a clock. That residual recurs for *any* future gate that evaluates an expiry, and it is
  exactly the kind of ongoing, tracked item the register exists for — the same shape as
  RISK-2026-0005 (the pre-shared-roots residual that outlived the wiring fix it came from).
- **Why its exposure is near-zero.** There was **no exploitable window**: nothing consumes an
  `AuthorizedAction` until the executor (Phase 11), which does not exist, so a stale-but-passing
  chain could authorize no real action. The instance is being **reduced to closure** now (this core
  rev → the gate rev → the Phase 8.5 rebuild), all before Phase 11, and is fully documented in ARCH
  Rev 1.15.

**Recommended entry (for DAP placement):** *RISK-2026-0006 — A gate may enforce a freshness expiry
against a clock held at construction (I-13 / OQGF-M-14). Source: Phase-8.5 buildability check;
disposed ARCH Rev 1.15. Likelihood Possible, Impact Major. Disposition Reduce — mitigation is I-13
(call-site parameter, enforced by type), per-crate review, and the workspace grep for a held
clock. Status: Open — SINDRI instance found and being fixed (core rev 18 Aug → gate rev → Phase 8.5
rebuild); residual is that core cannot force forwarding. Target: gate revision + Phase 8.5 rebuild,
before Phase 11.*
