**Record ID:** REDTEAM-15A-2026-08-24-R1
**Date:** 2026-08-24
**Type:** Adversarial testing (not construction). Document, don't fix. Findings continue from **F-22**.
**Perspective:** Grey hat — **partial** knowledge, two threat models exercised together:

**Test artifacts:** runtime attacks in `brokkr-cli/tests/redteam_15a.rs` (10 tests); trust-boundary attacks with no meaningful runtime assertion are documented here (§2). The governance-layer facts the attacker guesses at were confirmed by the builder against source (cited).

## 1. Summary

**~14 attack vectors across 3 categories (G1 design-assumption, G2 insider, combined). 10 runtime tests pass. 0 critical, 0 high.** Four findings (F-22 … F-25): one LOW code gap the prior phases missed, and three informational trust-boundary / doc-staleness observations.

| Category | Result |
|---|---|
| G1 — design-assumption attacks | The spine holds; two attacker assumptions are **refuted by a stricter-than-documented build** (F-25 conjuncts enforced), the rest map to named operational trust boundaries |
| G2 — insider tool-layer attacks | Every structural defense holds against insider knowledge; **one genuine gap** — the F-5 uniform stage is defeated by the denial *reason string* (F-22) |
| Combined | Knowing the gate order and the code gives the attacker *information* (which stage is next) but **no bypass** — every gate's defense is structural, not obscurity-based |

**The grey-hat result, in one line:** partial knowledge lets the attacker aim precisely, but the defenses are structural, so precise aim buys information (timing, stage, order) and not authority. The one place partial knowledge found a real gap is an *information* gap (F-22), not an authorization one. And in two places the hidden layer is **stricter** than the attacker's design-informed model predicted (F-25).

## 3. Findings (F-22 … F-25)

### F-22 (LOW) — the denial *reason string* defeats F-5's uniform denial stage
**Where:** `Orchestrator::execute_hop` — the genome-refusal path returns `reason: refusal.detail` (`brokkr-cli/src/lib.rs:501`), the SINDRI-anergy path returns `reason: format!("architectural anergy: {reason:?}")` (`:525`).
**What:** 13-FIX F-5 made the denial *stage* uniform (`Genome` → `Gate`) so a caller cannot tell a declared tool from an undeclared one by the stage. But the *reason string* still names the genome refusal verbatim ("tool X not declared"), which is distinguishable from a SINDRI anergy reason. An insider — or any caller that sees `HopResult` — recovers the genome-enumeration oracle F-5 aimed to close.
**Why LOW:** the caller of `execute_hop` is the trusted driver, and the *stage* (the machine-readable field integrations branch on) is uniform; the leak is in a human-readable string. But it is a genuine incompleteness of F-5 the prior phases missed. **Recommendation:** return a uniform reason string for a genome refusal under `uniform_denial_stage` (keep the true reason in SAGA, as F-5 already does for the stage), so both the stage and the reason are uniform.

### F-23 (INFO) — the orchestrator is in the trusted computing base
**Where:** `execute_hop` step 8 — the reconciliation `Observation::Hop { authorized, executed: Some(action) }` copies `action` into both fields (`brokkr-cli/src/lib.rs`).
**What:** HEIMDALL is fed observations the orchestrator *constructs*; it does not — and structurally cannot — independently verify that the executed action matches the authorized one, nor that a reported success actually occurred. A compromised orchestrator can feed HEIMDALL any self-consistent observation (and mis-stamp SAGA). This is inherent: the deterministic orchestrator is trusted by design (the prime directive isolates the *model*, not the harness). **Named because §13 does not currently enumerate the orchestrator's TCB membership**, and a grey-hat attacker probing "who watches the watchmen" lands here. Not a defect — a trust boundary worth stating. **Recommendation:** record the orchestrator's TCB role in the threat model; the 14-FIX F-20 improvement (failed executions → `executed: None`) is an honesty-of-observation gain, but the orchestrator remains the observer.

### F-24 (INFO) — no signed REGIN genome is wired into the orchestrator
**Where:** the `GenomeCheck` port (`brokkr-cli/src/lib.rs`) and every test's genome double.
**What:** the architecture's signed `Genome` (tool register, policy, roots-of-trust — Rev 1.4/1.5, Phase 5 REGIN) exists as types and a promotion gate, but the orchestrator's *per-hop* `GenomeCheck` is a port backed by whatever the composition root supplies (test doubles in the current tree). The "closed vocabulary" is only as trustworthy as the wiring. **Expected at this build stage** (the executor is wired last; production wiring of a signed, independently-verified genome is deployment work) — named so it is a tracked deployment gap, not a silent assumption. **Recommendation:** wire the signed REGIN genome (with signature verification at load) into the production composition root; the promotion gate already proves the machinery.

### F-25 (INFO) — the spine enforces all four conjuncts; the §6.4/§13 "deferred" residual is closed in code
**Where:** `brokkr-gate/src/sindri.rs:147-194` — `evaluate` enforces, in order, Signal 1, Signal 2, **action-in-scope (conjunct 3)**, and **action-respects-invariants (conjunct 4)**.
**What:** BROKKR-ARCH Rev 1.17 §6.4 and §13 record two of OQGF-M-11's four conjuncts as *deferred / PARTIAL*, bounded by the Deferred-Conjunct Deadline (enforce before the executor is wired at Phase 11). **The current build meets that deadline** — SINDRI denies an out-of-scope action (`OutOfScope`) and an invariant-violating one (`InvariantViolated`), confirmed at runtime (a {read} chain denies `write_file`). A G1 attacker relying on §13's wording underestimates the spine. **Not a defect** — a vindication and a documentation-staleness observation: the code is stricter than its documented residual state. **Recommendation:** an architecture revision may downgrade the §13 residual and update the M-10/M-11 traceability verdicts from PARTIAL toward satisfied (a DAP-placed change, not the builder's).

## 4. Confirmed-sound against partial knowledge (the grey-hat "PASS" list)

- **Structural, not obscurity-based.** Every gate's defense (unforgeable `AuthorizedAction`, monotonic attenuation, deterministic Deny, non-suppressible gates) holds whether or not the attacker knows the design or the orchestrator code. Combined knowledge adds information, not bypass.
- **The spine is stricter than the design-informed attacker models it** (F-25): all four conjuncts enforced.
- **Parser and sandbox hardenings hold under insider aim** (F-16 first-pair, F-8 sanitization, F-2 lexical boundary — the last a *named* limitation).
- **The one gap is informational** (F-22 reason-string oracle), not an authorization bypass.

## 5. Scope honesty

High-noise grey hat: obvious attacks from a partially-informed attacker, aimed by partial knowledge at the hidden layers. The three trust-boundary findings (F-23 SAGA/orchestrator TCB, F-24 unsigned genome wiring, and the operational items 1.3/1.4/2.7) are **operational and deployment** assumptions, not code defects — they are what a grey hat *correctly* identifies as the soft edges of any governed system: key custody, cert management, composition-root trust. The one code gap (F-22) is LOW and named with a concrete fix. Not covered, and left to a dedicated effort: fuzzing the parser/JSON extractor under adversarial insider inputs, and a live-deployment review of cert/key custody (the 1.3/1.4 residuals, which are outside a hermetic test's reach). The next round (15B/15C, lower noise) is where a grey hat's *subtle* assumption-violations would live.
