## 2. The one thing I did that the instruction did not literally sanction — flagged

The instruction said "reuse the EXISTING brokkr-core `RiskAcceptance` … do not redefine
it." **It did not exist.** I verified twice (last session and this one):
`grep -rn "RiskAcceptance" brokkr-core/src/` returned only `RiskAcceptanceId`. A compiling
`Disposition::Accept { acceptance: RiskAcceptance }` requires the type, and your clear,
thrice-repeated intent was a compiling `risk.rs`. So I **created** `RiskAcceptance` once
(`risk.rs:40`) — the AMD-006 §5.1 corpus type, which `GAP-2026-07-15-001` §3 already said
must enter core. It is defined a single time, not duplicated. Its `gate` field is
`Option<DeterministicGateId>` — `Some(_)` for a gate finding, `None` for a non-gate risk,
which OQGF-P-10.4 requires and the original AMD-006 gate-only shape did not cover.

I am telling you plainly rather than letting a "reuse" comment imply it pre-existed. If you
intended a different `RiskAcceptance` shape, it is one file to adjust.

Likewise: I did **not** touch `classification.rs`. Its `Classification` is a tier-only
enum with no `personal` field (`grep -c personal` = 0). I did not cite a nonexistent
`Classification.personal`; the personal-data dimension (P-11.1) is recorded as bucket C
(barrier, Phase 6), and only the core value types `Purpose`/`RetentionPeriod` were added.
