## 0. The one cross-cutting design decision (read this first)

Four of the fixes — **F-1 replay, F-5 uniform denial stage, F-7 rate limit, F-9 monotonic time** — change **observable orchestrator behavior** that dozens of existing red-team tests deliberately exercised (reusing one chain, flooding, asserting `DenialStage::Genome`, running a backward clock). The task requires the **production default to be safe** *and* the existing red-team tests to keep verifying the spine. Those two goals collide unless the new behaviors are configurable.

**Resolution — the four behavioral guards are a configurable `Guards` value; `Orchestrator::new` defaults to `Guards::production()` (all on, 100 hops/60 s).** A test rig that verifies the deterministic **spine** (the red-team suites, and the Phase-11 composition tests) opts into `Guards::permissive()` — so it can legitimately reuse a chain or observe the true denial stage — while the new guards get their own dedicated regression tests under production settings (`redteam_fix.rs`). This keeps the red-team suite meaningful (it still probes SINDRI/HÚÐ/genome), keeps production strict, and gives each guard a real test.

**F-3 (size) and F-8 (audit sanitization) are *unconditional*** — pure safety transforms that cannot break a legitimate test (a <1 MiB detail is unaffected; sanitization only strips control bytes, and the red-team tests that recorded control bytes are updated to assert the stripping). **F-4 and F-6 are structural** — enforced by the compiler and by removing a code path, so they need no config.

## 1. The fixes

### F-2 (MEDIUM) — tool-layer path validation
`brokkr_tools::SandboxedTool`: constructed over a canonicalized `root`, it resolves a requested `detail` **lexically** (`.`/`..` folded without touching the filesystem, so a not-yet-existing target is still checkable), joins it onto the root, and returns a `ToolError` (never a panic) if the result escapes the root. `execute` writes only inside the sandbox. This is where the §13 detail residual is properly closed — **the tool validates its own input**, because the spine treats `detail` as opaque by design.
**Regression:** `fix_f2_path_traversal_denied_by_tool` (`../../../etc/passwd` → `Err`), `fix_f2_legitimate_path_within_root` (`safe.txt` → `Ok`, under the root).

### F-6 (MEDIUM) — strict parser only
Removed the lenient prose-mining fallback (`mentions_word`, `first_abs_path`) from `brokkr_reasoner::ollama::parse_action`. It now accepts **only** the strict `TOOL:`/`PATH:` lines; anything else yields tool `unknown`, which the genome denies (fail-closed). A prose sentence mentioning a verb and a path can no longer become an actionable proposal.
**Regression:** `fix_f6_strict_format_still_works`, `fix_f6_prose_no_longer_parsed`; the 13B `attack_3_6` and the Phase-12 shell-style/echo tests updated to assert `unknown`.

### F-4 (MEDIUM) — concurrent-signing soundness, enforced by the compiler
`DualKeyPair::sign_dual` is now `&mut self`, and `DualKeyPair` carries a `PhantomData<Cell<()>>` marker that **removes its auto `Sync` impl**. Concurrent signing on one keypair through a shared `&` — which raced on the wolfCrypt key/RNG state and silently corrupted signatures — is now a **compile error**, not a discipline. Holders that sign from a `&self` method (SAGA, HEIMDALL) keep the keypair behind a `Mutex`. **Ripple:** 71 call sites across 20 files updated (signing params → `&mut`, keypair bindings → `mut`). Verification is untouched (`DualPublicKey` stays `Sync`).
**Regression:** two `compile_fail` doctests in `brokkr-crypto` — E0596 (can't sign through `&`) and E0277 (`&DualKeyPair` isn't `Send` because the type is `!Sync`).

### F-1 (MEDIUM) — chain replay guard
The orchestrator keeps a `(principal, nonce) → expiry` map (behind the guard `Mutex`); a chain whose nonce was already used within its expiry is `Denied{Gate, "chain replay detected"}`. Expired entries are evicted first, so a genuinely fresh chain is never blocked. SINDRI stays stateless and deterministic — the replay ledger is a **driver** concern (mirroring EIR's nonce ledger for resolution decisions).
**Regression:** `fix_f1_replay_denied`; 13A `attack_2_4` updated to assert the second hop is denied.

### F-3 (LOW) — max detail size
`const MAX_DETAIL_BYTES = 1 MiB`. After MÍMIR proposes and before REGIN, an oversized `action.detail` is `Denied{Gate, "action detail exceeds size limit"}`. Unconditional.
**Regression:** `fix_f3_oversized_detail_denied` (2 MiB → denied), `fix_f3_normal_detail_allowed`; 13A `attack_5_6` updated to assert denial.

### F-5 (LOW) — uniform denial stage
Under `production` guards, a genome refusal returns `DenialStage::Gate` (the same stage SINDRI produces), so the caller cannot use the stage to distinguish a declared tool from an undeclared one — the genome-enumeration oracle is closed. **SAGA still records the true genome reason** (the audit is trusted). Configurable (permissive rigs still report `Genome`, so the red-team suite keeps verifying the distinction exists internally).
**Regression:** `fix_f5_genome_denial_presents_as_gate`.

### F-7 (LOW) — per-hop rate limit
Sliding-window limiter (`VecDeque<Timestamp>`), default 100/60 s. Over the limit → `Denied{Gate, "rate limit exceeded"}`.
**Regression:** `fix_f7_rate_limit_enforced` (5/60 s, 6th denied); 13C `attack_2_2` updated.

### F-8 (LOW–MED) — audit-content sanitization
`sanitize_for_audit` strips control characters (below 0x20 except `\n`/`\t`, plus DEL) and drops ANSI CSI escape sequences, applied to the **audit copy** of `detail` and `rationale` before recording. Lossy by design — a recorded value cannot truncate/recolor/corrupt a log viewer. The real `Action.detail` handed to the barrier and tool is untouched. Unconditional.
**Regression:** `fix_f8_control_chars_stripped`, `fix_f8_unit_newline_and_tab_preserved`; 13C `attack_3_3` updated to assert stripping (3.1 still passes — newlines are preserved).

### F-9 (LOW) — monotonic-time guard
The orchestrator remembers the last accepted `now`; a hop whose `now` precedes it is `Error{"non-monotonic time rejected"}`. `now` is still a per-call parameter threaded to every gate — the remembered value is the *previous* time, used only to detect regression, not a held evaluation clock (I-13 unaffected; see §3).
**Regression:** `fix_f9_backward_clock_rejected`; 13C `attack_1_4` updated.

### F-10 (INFO) — undeclared-capability validation
`validate_scope(scope, vocabulary) -> Vec<Capability>` returns the capabilities in a Root Intent's scope that are not in the recognized vocabulary. A **warning surface**, not a denial — an undeclared capability grants nothing, so a hard error would be over-denial (OQGF-P-1). A driver calls it at Root-Intent construction and logs the result.
**Regression:** `fix_f10_undeclared_capability_reported`.

## 3. Invariant notes

- **I-13 (freshness is a per-call parameter):** unaffected. `execute_hop` still takes `now` and threads it to every gate. The F-9 `last_now` remembers the *previous* call's `now` to detect a regressing clock — it is never read to evaluate a freshness/expiry (that still uses the call parameter). The held-clock grep matches only `Orchestrator::now()`, the intended §4 reader.
- **I-1 / I-12:** untouched — the orchestrator still mints nothing; `AuthorizedAction` comes only from `gate.authorize`, `ClearedContext` only from `clear`.
- **F-4 and the `Sync` boundary:** `MlDsaSigner`/`SlhDsaSigner` still require `Sync` and hold the ffi key types (whose `unsafe impl Sync` is retained — a single-signer wrapper, used from one place). Only `DualKeyPair` (the dual-family signer that was being shared) drops `Sync`.

## 4. Honest notes

- **The behavioral guards default ON in production but OFF in the spine-verifying rigs.** This is a deliberate, documented separation: the red-team suites verify the deterministic spine (which is what they were written for), and the new driver guards are verified by `redteam_fix.rs` under production settings. A reader who wants "do the red-team attacks still fail against a *fully production-guarded* orchestrator" gets a stronger-but-narrower answer from the fix tests; the red-team suite answers "does the spine still hold."
- **F-2 canonicalization is lexical for the target path** (the root itself is symlink-resolved at construction). A symlink *inside* the sandbox root pointing outward is not followed by the lexical check; production deployments that allow untrusted symlink creation inside the root should additionally canonicalize the final path. Named, not silently assumed away.
- **F-4 ripple was mechanical and compiler-verified** — the workspace does not compile until every one of the 71 sites is `&mut`, so there is no silent-miss risk.
