## 2. Fixes

### Fix 1 — `KillSwitch` latch (F-36; also hardens ordering)

`brokkr-cli`: the bare `kill_flag: Arc<AtomicBool>` (freely `store(false)`-able) is replaced by a `KillSwitch` type exposing only `kill()` / `is_killed()` / `handle()` — **no unset**. Once set, the session stays killed; a compromised thread that activated it cannot be overridden by another clearing it. The type also hardcodes `Release`/`Acquire`, so a caller cannot weaken the ordering to `Relaxed`. `Orchestrator::kill_handle()` → `kill_switch() -> KillSwitch`; `run_hop` reads `self.kill_switch.is_killed()` before every gate.
- **Regression:** `redteam_16::fix_kill_switch_is_a_latch` (killed stays killed; a second handle sees the latch; no clear API). Fails against the pre-fix `Arc<AtomicBool>`.
- **Ripple:** `tests/capability.rs` kill tests converted (`kill_handle().store(true, Release)` → `kill_switch().kill()`), now-unused `Ordering` import removed there and in `redteam_16.rs`.

### Fix 2 — egress destination normalization (F-35)

`brokkr-cli`: `check_egress` now normalizes both the incoming host and each manifest rule's destination via `normalize_destination` (lowercase, trim, fold `127.0.0.1`/`::1` → `localhost`) before comparing, so the same endpoint spelled differently cannot bypass the manifest nor be falsely denied. Conservative: no DNS resolution — the deterministic gate must not depend on a lookup.
- **Regressions:** `redteam_16::fix_egress_ip_hostname_equivalence` (127.0.0.1 admitted against a `localhost` rule — fails pre-fix), `fix_egress_still_denies_unknown` (normalization does not broaden). The Phase-16 F-35 representation test was converted in place to the fixed behaviour (renamed, not deleted). The `"*"`-is-literal half of F-35 stands (`f35_egress_star_is_literal_not_wildcard`).

### Fix 3 — `permissive()` validates (safety net on the F-32 area)

`brokkr-core`: `CapabilityEnvelope::permissive()` ends with `debug_assert!(validate().is_ok())`, so a future edit that makes the library default's tiers inconsistent fails during any debug/test run. `debug_assert` (not a hard error) because `permissive()` is a composition/test default and a hard error would panic setup.
- **Regression:** `redteam_16::fix_permissive_validates`.

## 3. Accepted findings (with rationale)

Documented in the new dated boundaries record `reports/SECURITY-BOUNDARIES-2026-09-01-R1.md` (a new file, not an edit to the 2026-08-30 record — §8 never-overwrite).

| ID | Sev | Why accepted (not fixed this phase) |
|---|---|---|
| **F-32** | LOW-MED | `with_envelope` is a documented caller-contract; Fix 3 guarantees the *library* default is valid. A validating install path (or `try_with_envelope`) is a design decision the DAP prescribed only for `permissive()` — **referred to the DAP.** |
| **F-33** | MEDIUM | `permissive()` is the intended default (Fix 3 hardens it); a deployment supplies `.with_envelope(..)`. A deny-safe default would change construction semantics for many callers — **referred to the DAP.** Recorded as the P-12.1/2 PARTIAL. |
| **F-34** | MEDIUM | Enforcing port/protocol needs a `Destination::Network` field — a governing `brokkr-core::barrier` type change that touches HÚÐ. Out of scope for a hardening pass — **referred to the DAP.** Recorded as the P-12.4 PARTIAL. |
| **F-37** | LOW | By design (pre-hop check; ARCH §6.13). Latency bounded by the longest tool call — a bound, not a cooperation dependency. Aborting a tool mid-execution could leave the filesystem inconsistent; the tool is sandboxed and the action was already authorized. |
| **F-38** | LOW-INFO | Trajectory is in-memory; durable reconstruction rests on the SAGA event stream — same shape as F-30 (SAGA durability ⇐ external persistence). |

**Why the two MEDIUM findings are accepted rather than fixed.** Both F-33 (fail-open default) and F-34 (port/protocol) are genuine gaps between AMD-011 and the wiring, but closing each is a *decision*, not a mechanical fix: F-33 flips a default that many callers rely on, and F-34 changes a governing type. The DAP's 16-FIX task prescribed exactly three fixes (latch, normalization, permissive-validate) and did **not** prescribe these — consistent with the DAP deferring them, likely pending the Rev 1.18 / v1.8 drafts (where the drafted invariant I-14 "validated before it governs" is stronger than the code, a mismatch this red-team surfaced). Per §4, the builder does not unilaterally change a governing surface or a construction default; it implements what is prescribed, records the rest as PARTIAL, and refers the decision up.
