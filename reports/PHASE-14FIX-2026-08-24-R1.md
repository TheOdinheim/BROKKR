## 0. The three findings accepted with no code change (read first)

The task classifies these as informational/inherent, and the 14A/14C reports already document them accurately. No regression test — there is no behavior to change.

- **F-11 — "the guarantee is a private minter, not a sealed trait."** `CostimulationGate::authorize` / `ContextClearance::clear` are *not* sealed; an implementor may override them, but the override cannot construct a token because `mint` is module-private. The committed doctests (14A 2.1/2.2, E0624) already prove the real, stronger mechanism. Nothing to change.
- **F-12 — `forbid(unsafe_code)` is a crate attribute a doctest does not inherit.** The 14A 1.5 transmute doctest already carries `#![forbid(unsafe_code)]` inside itself, demonstrating the property that holds in every non-crypto crate (E0133). Nothing to change.
- **F-21 — timing side channels are inherent to variable-cost cryptographic work.** A dual-family verification *is* ~1000× a hashmap lookup; adding a fixed floor delay to equalize would waste resources without helping (relative differences remain measurable), and the party who can time `execute_hop` is the **trusted driver**, not the untrusted model (which sees neither latency nor `HopResult`). Accepted as an inherent property; a floor delay is warranted only if `HopResult` is ever exposed to a less-trusted caller, which it is not.

## 1. The fixes

### F-13 (LOW) — the replay-nonce ledger is bounded
`brokkr-cli`: `MAX_NONCE_ENTRIES = 10_000`. In `check_guards`, the replay check runs first (a resubmitted nonce is denied regardless of the cap); then, only when inserting a genuinely-new nonce at capacity, the entry with the **smallest expiry** (nearest legitimate eviction) is evicted. A malformed far-expiry chain (e.g. `u64::MAX`, itself out of bounds under OQGF-M-14) can no longer grow the ledger without bound. The ledger never *forgets* a still-fresh nonce preferentially, so it cannot wrongly admit a normal-chain replay.
**Regression:** `fix_f13_nonce_ledger_bounded` — fill `MAX+1` distinct far-expiry nonces (nonce_0 given the smallest expiry so it is the eviction target); resubmitting nonce_0 is **admitted** (evicted → proven bounded), resubmitting nonce_1 is **replay-denied** (still remembered → did not forget wholesale).

### F-14 (LOW) — unterminated ANSI CSI drop is bounded
`brokkr-cli`: `sanitize_for_audit` caps the CSI-skip at 16 chars. An unterminated CSI (ESC `[` followed only by parameter bytes to EOF) previously consumed the whole tail, letting an attacker truncate a recorded value by appending a lone `ESC [`. Now at most 16 bytes are dropped; the rest survives. A terminated CSI (`ESC [ 3 1 m`) is still fully stripped (F-8 render-safety preserved).
**Regression:** `fix_f14_unterminated_csi_bounded` (40 `;` param bytes → >20 survive), `fix_f14_terminated_csi_still_stripped` (`\x1b[31mred` → `red`).

### F-15 (LOW) — empty path rejected by the sandbox
`brokkr-tools`: `SandboxedTool::resolve("")` returns a `ToolError` at the sandbox layer, instead of resolving to the root directory and relying on the filesystem to refuse the write. An empty path is never a valid write target.
**Regression:** `fix_f15_empty_detail_rejected` (`""` → `Err`, `safe.txt` → `Ok`); 14B `attack_6_5` updated (`..._resolves_to_root_dir` → `..._rejected`).

### F-16 (LOW) — parser takes the FIRST TOOL/PATH pair
`brokkr-reasoner::ollama::parse_action`: `get_or_insert_with` keeps the first `TOOL:`/`PATH:` pair. An attacker who controls the model's output *suffix* (a poisoned continuation) can no longer override an earlier benign pair. The result is still gated by SINDRI; this shrinks the parser's ambiguity, it is not a spine change.
**Regression:** `fix_f16_first_pair_wins`; the 13B `attack_3_1`/`attack_3_4` and 14B `attack_2_3` last-wins tests updated (renamed to `..._first_..._wins`) to assert the new behavior.

### F-17 (LOW/INFO) — `json_string_field` returns None on truncation
`brokkr-reasoner::ollama`: an unterminated string value (no closing quote, or a trailing backslash mid-escape) returns `None` rather than a partial value. The backend then surfaces a clean error rather than a silently truncated string that could leak internal state or be mis-parsed.
**Regression:** `fix_f17_truncated_returns_none`; 14B `attack_2_6` updated (partial → `None`).

### F-18 (INFO → hardened) — SLH-DSA signature-size cross-check
`brokkr-crypto::ffi`: `SlhDsaShake192s::generate` now checks `sig_size() == SLHDSA192S_SIG_SIZE` (16224) and returns `Err` on mismatch — symmetric with `MlDsa65::generate`. A wrong SLH-DSA parameter set is caught at keygen. **Verified in Step 0:** the linked `libwolfssl` reports 16224 for `192s` (the FIPS-205 small variant); the red-team report's 35664 is the *192f* (fast) variant, which would have failed every keygen — the constant was verified against the library before use. Defense-in-depth (the sign buffer was already library-sized), not a memory fix.
**Regression:** `fix_f18_slhdsa_sig_size_checked` (keygen succeeds ⇒ the guard passed; the produced signature is exactly 16224 bytes).

### F-19 (LOW) — bounded TLS read
`brokkr-crypto::tls`: `MAX_RESPONSE_BYTES = 10 MiB` and a new `TlsError::ResponseTooLarge`. `read_until_close` aborts past the cap, so a peer that streams without closing cannot drive the client to OOM. 10 MiB is far above any model response (an ollama reply is < 100 KiB).
**Regression:** `fix_f19_response_bound_exists_and_reasonable` (the cap is in a sane range and the overflow error renders — an infinite-stream peer cannot be exercised hermetically, so the bound is verified structurally, as the task directs).

### F-20 (LOW) — HEIMDALL observes tool failures
`brokkr-cli`: on a `tool.execute` `Err`, `execute_hop` now feeds HEIMDALL `Observation::Hop { authorized, executed: None }` before returning `HopResult::Error`. A failed *authorized* execution is visible to the reconciliation loop, so a pattern of authorized-but-failing tools (a possible tamper/resource signal) is detectable rather than invisible.
**Regression:** `fix_f20_tool_failure_observed`; 14C `attack_5_1` updated (`..._is_invisible_to_heimdall` → `..._is_observed_by_heimdall`).

## 4. Honest notes

- **F-18's constant was corrected during Step 0.** The 14C report cited 35664 (the `192f` fast variant); the linked library reports 16224 for `192s`. Using 35664 would have made `generate()` reject every legitimate key. The value was probed against the real `libwolfssl` before the guard was added, and the test asserts both the correct value and the rejection of the wrong one.
- **F-19 is verified structurally, not with a live infinite-stream peer.** A hermetic test cannot make a server stream forever; the regression verifies the bound exists, is reasonable, and that the overflow is a clean error value — as the task directs. The bound is documented on the function.
- **F-14 is lossy for pathological-but-legit CSI sequences** longer than 16 body bytes (rare): the cap re-emits the overflow as text. The audit copy is for human review and is lossy by design (F-8); the decision content is untouched. Named, not assumed away.
- **F-16/F-17 harden the parser, which is not the spine.** They reduce prompt-injection ambiguity; the deterministic gate still decides. This is the same "parser is not the gate" boundary the 13-FIX F-6 fix named.
