## 1. What SINDRI is, at the Phase-4 scope

`brokkr-gate` implements `CostimulationGate::evaluate` and **nothing that mints**. It enforces
the two cryptographic conjuncts of OQGF-M-11 that Rev 1.3 §6.4 assigns to Phase 4:

- **Signal 1 (identity, M-1):** the presented identity **resolves** to a declared root of trust
  **and binds** to the hop the chain's signature proves (final entry, or `root.principal` for a
  root-only chain). The attestation's own `signatures` are not checked (Rev 1.3 §6.4 drops it as
  redundant with Signal 2; the committed types define no attestation signed-content).
- **Signal 2 (chain, M-8/M-9/M-14):** resolve the root and every hop key through the resolver
  seam, then `Skuld::verify_chain_public(root, entries, &root_pub, &hop_refs, self.now)`, mapping
  `IntentError → AnergyReason` exactly per the §6.4 table.

Conjuncts 3 (action-in-scope) and 4 (action-respects-invariants) are **deferred** under the
Deferred-Conjunct Deadline; SINDRI builds nothing for them.

## 3. Deviations from the placed sketch (all additive — reported for DAP review)

The prompt flagged that the architecture's code blocks have been illustrative before (Rev 1.2's
`authorize` sketch was inverted in committed core), and asked me to record deviations. There are
**three**, none of which changes a committed type or relaxes a requirement:

### 3a. `KeyResolver::resolve_subject` added (§6.4.1 sketched only `resolve(attestation)`)

The root carries `RootIntent::principal: SubjectId` and **no `Attestation`**, so its key cannot
be obtained through `resolve(attestation)`. I added `resolve_subject(&SubjectId)` as the required
method, with `resolve(attestation)` a **default** delegating to
`resolve_subject(&attestation.subject)`. The placed method exists unchanged and its semantics are
preserved; this only adds the subject-keyed lookup the root needs. **Judged additive** (it adds a
method, removes/weakens nothing). Not filed as a gap, because it does not change or relax the
placed interface — it completes it for the root case the sketch could not express.

### 3b. `now` held in `Sindri` state (committed `evaluate` carries no `now`)

The committed `CostimulationGate::evaluate(&self, identity, chain, action)` has **no `now`**
parameter, yet `verify_chain_public` requires one and Rev 1.3 §6.4 mandates freshness be "a
parameter, never a wall-clock read." The only way to satisfy both, given the committed trait, is
to inject the evaluation time at construction: `Sindri::new(resolver, now)`, threading `self.now`
to `verify_chain_public`. SINDRI **never reads a clock**; the Phase-11 orchestrator constructs a
`Sindri` with the current time per evaluation (documented on the type). This deviates from the
§6.4 **mermaid**, which *illustrates* `evaluate(identity, chain, action, now)`; the committed
trait is authoritative and the mermaid is illustrative. **Judged additive** — no committed type
changes, freshness is still enforced (M-14), nothing is relaxed. Tests exercise it directly
(`test_oqgf_m_14_expired_chain_is_anergy` constructs with `now > expiry`).

### 3c. The broadened-chain test is unconstructable at the SINDRI boundary (I-3)

`Sindri::evaluate` takes an `&IntentProvenanceChain`, whose only constructors are `new` +
`extend`; `extend` refuses a non-subset `emitted_scope` (I-3 / OQGF-M-9) and there is no
deserialization path. So a **broadened chain cannot be built** to hand to SINDRI — the bad state
is unrepresentable, which is stronger than a runtime test. The requested
`test_oqgf_m_9_broadened_chain_is_anergy` is therefore not written as a SINDRI-level test; the
`WouldBroaden → ChainInvalid` mapping is present in `map_intent_error` (for a future reconstructed
chain) and exercised at the verifier level in
`brokkr-intent/tests/chain_public.rs::test_verify_chain_public_rejects_tampered_entry`. In its
place, two **reachable** `ChainInvalid` arms are tested (`test_tampered_entry_signature_is_anergy`
via a wrong signature, `test_broken_hash_link_is_anergy` via a wrong hash link), both built with
`extend` (which is subset-guarded but not signature-/digest-guarded). This is stated in the test
module doc, the test record, and the conformance check (§3 there) — not glossed. **Not a gap:**
SINDRI is complete and its mapping is correct; the unrepresentability is a property of I-3, and I
report it rather than fabricate a test for an impossible input.

## 4. Structural confirmations (the load-bearing guarantees)

- **I-1 — SINDRI cannot mint.** `brokkr-gate/src` contains no `AuthorizedAction { … }`
  construction, no `::mint` call, and no `authorize` override (verified by grep). SINDRI supplies
  only `evaluate`; the sole minter is core's provided `authorize`, whose `mint` is module-private.
  `test_i1_sindri_never_mints` confirms a failure routes to `Anergy`. Fail-safe by construction:
  the worst SINDRI can do is wrongly deny.
- **Conjuncts 3–4 unreachable.** `AnergyReason::OutOfScope` and `::InvariantViolated` are **never
  constructed** in `brokkr-gate/src` (grep finds them only in doc comments). `evaluate` returns
  `Ok(())` after Signals 1–2; `map_intent_error` yields only `IdentityUnverified` / `ChainExpired`
  / `ChainInvalid`. The deferral is enforced by the absence of any constructing path, not a flag.
- **I-5.** `cargo tree -e no-dev` = `{brokkr-core, brokkr-crypto, brokkr-intent}` — no
  reasoner/tools/cli. **I-6.** No model calls; pure logic; no network, no FFI;
  `#![forbid(unsafe_code)]`.
