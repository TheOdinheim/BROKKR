## 1. What this revision does

Rev 1.4 grows REGIN from four signed registers to **six** and places the surfaces Phase 5 needs to
close the two conjuncts SINDRI deferred at Phase 4. This revision adds **types only** — no promotion
gate, no key resolver, no evaluation logic (all Phase 5). Scope-locked to `brokkr-core`.

**New types** (`genome.rs`): `AlgorithmId`, `RootOfTrustEntry`, `RootsOfTrust`, `InvariantEntry`,
`PolicyRegister`. **Extended types**: `ToolEntry` (+`required_capabilities`), `Cbom`
(+`algorithms`), `VendorTrustScore` (+`reconciliation_pass_rate`), `Genome` (+`roots`, +`policy`,
`new` 8→10 args).

## 3. The load-bearing part: the doctests (I-10)

`Genome::new` went from 8 to 10 arguments. Had I left the doctest at 8 args, it would still have
*failed to compile* — but for **arity (E0061)**, not the **E0308 type mismatch** it exists to
prove. A doctest that passes for the wrong reason proves nothing. So:

- The signature doctest was updated to **10 args** with `None` as the 10th, keeping the failure on
  the **signature field** — verified `E0308`.
- A **new third doctest** proves the same for the new required `roots` register: `Genome::new(…,
  None, …)` with `None` at the 6th (`roots`) position fails **E0308** (`expected RootsOfTrust,
  found Option<_>`). This is the Rev 1.4 extension of I-10, proven the same way the original was.
- All error codes were **verified by running** the doctests (rustdoc checks the emitted code) — not
  guessed. genome.rs compile-fail fences: **2 → 3**; brokkr-core running doctests: **11 → 12**
  (the `lib.rs` "compile_fail" is prose, 0 fences), and `cargo test --doc` = **12 passed**
  confirms the new one runs.

## 4. The one downstream touch — investigated, not papered over

`cargo test --workspace` surfaced `E0063: missing field reconciliation_pass_rate` at
`brokkr-core/tests/negative_invariants.rs:469`. Per instruction I investigated rather than
patched blindly:

- The break is in **brokkr-core's own** integration test (`trust_score()` helper), **not** a
  downstream crate. A workspace grep confirmed it is the **only** struct-literal construction of any
  extended type anywhere — no `Cbom`/`ToolEntry`/`Genome`/`VendorTrustScore` literal exists in
  `brokkr-crypto`, `brokkr-intent`, or `brokkr-gate`. This confirms the premise "nothing downstream
  consumes `Genome`": the downstream crates use `brokkr-core` types they don't *construct* here.
- Fix: added `reconciliation_pass_rate: Score(0)` (a placeholder, matching the field's
  unmeasured/PARTIAL status). This is a required update to brokkr-core's own test for the new
  required field — in scope (touches brokkr-core only), and it is not "papering over" a surprise:
  the surprise was investigated and shown to be exactly the expected consequence of adding a
  required field to a type brokkr-core's own tests build.

## 6. Structural invariants

- **I-5 held, by the raw-bytes choice.** `RootOfTrustEntry` declares raw `Vec<u8>` public keys, not
  `DualPublicKey` (which lives in `brokkr-crypto`, a downstream crate). A core register holding
  `DualPublicKey` would invert the dependency direction. `brokkr-core` still depends on nothing.
  Documented in the type as load-bearing, not incidental (§6.2 line 308).
- **I-10 held and extended.** `roots` and `policy` are required (no `Option`); the new doctest
  proves it.
- **I-11 unaffected.** `ModelEndpoint::client_cert` remains a required field; that doctest is
  unchanged (ModelEndpoint gains no field this revision).
