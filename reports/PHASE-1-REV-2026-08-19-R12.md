## 1. What this revision does

Disposes GAP-2026-08-19-001 by adding **two** variants to `AdaptError`, exactly the option A / two-variant recommendation the gap's §6 preferred:

| New variant | Message | Category |
|---|---|---|
| `SubstitutedCorpus` | *"the evaluation corpus digest does not match the declared record (OQGF-P-6.2)"* | tampering (attack) |
| `StaleCorpus` | *"the evaluation corpus is not the current version (OQGF-P-6.2)"* | drift (not an attack) |

Both are **corpus-validity** failures — failures of the *evidence*, not the *candidate*. They exist so that `select` (and, for `StaleCorpus`, `activate`) can refuse a substituted or stale corpus **without falsely claiming a candidate defect** by reusing `Overfit`/`CoverageRegression`. Containment (a corpus that *contains* the seeding sample) stays `Overfit` — that claim is true — and no variant was added for it.

This is a **types-only** revision: it adds the refusal vocabulary. The gate that returns these variants is `brokkr-adapt` (Phase 9), which does not exist.

## 2. Why two variants, not one

The gap's §6 and the `ResolveError` precedent (Rev 1.13) both turn on the same point: **an error variant is a claim about what happened, and a false claim in a refusal is a false claim in the audit record.** A substitution (digest mismatch) is a corpus *chosen to make the candidate look good* — a poisoning attack — while a stale version is an *old but genuine* corpus — drift. A forensic reader needs them apart: a substitution says *investigate the corpus supply*, a stale version says *re-run against the current corpus*. Collapsing them into one `CorpusInvalid` would file "someone poisoned your evidence" and "your evidence is out of date" under one word — the same reason `Expired` and `ReplayedNonce` are two variants.

The `AdaptError` enum-level doc records this and cites the correction as **one principle applied four times**: `ToleranceError::SignatureInvalid` (Rev 1.12), `ResolveError::{Expired, ReplayedNonce}` (Rev 1.13), and these two (this revision). Doc style and the "false claim in the audit record" wording mirror the two prior corrections verbatim in spirit.

## 3. The code path (RISK-2026-0007 — name the path, not the type)

For a types-only revision the "code path" that satisfies the requirement is the **`Display` impl** the `error_enum!` macro generates and the variants' existence. The new test
`test_oqgf_p_6_2_corpus_validity_errors_name_the_evidence_not_the_candidate`
(`brokkr-core/tests/negative_invariants.rs`) exercises that path end to end: it calls
`AdaptError::SubstitutedCorpus.to_string()` / `StaleCorpus.to_string()`, asserts each names the **corpus/digest/version** (the evidence) and contains **no** mention of "candidate", and asserts they are distinct from each other and from `Overfit`/`CoverageRegression`. **That test would fail if a future edit reworded a corpus-validity message to imply a candidate defect** — which is the exact regression the gap exists to prevent. (It cannot yet test a *gate* returning these variants — that gate is Phase 9 — so it tests the honest-message property this revision is responsible for.)
