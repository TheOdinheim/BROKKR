## 1. What this revision does, and why it is more than one line

The core R11 revision added `version` and `produced_at` to `ScreenPass`. The workspace had exactly
one error — E0063 at `brokkr-sentinel/src/heimdall.rs:406`, HEIMDALL's `ScreenPass` initializer
missing `produced_at`. This revision supplies it and makes the workspace green.

Supplying `produced_at` **honestly** was not a one-line change, and the reason is the producer-signature
question PHASE-1-REV-2026-08-19-R11 §4 flagged for the DAP:

- `produced_at` SHALL be a per-call `now` (I-13, §6.12) — never stored, never defaulted.
- HEIMDALL's `screen` is an impl of the **core** `ToleranceController::screen`, whose committed
  signature carries **no `now`**. The core trait is out of scope and cannot gain one without also
  breaking core's own `MockController` test.
- The only other source for the time is a held `now` field — **exactly the defect I-13 forbids and
  the sentinel removed in R2.**

A trait cannot be partially implemented, so `screen`'s need for `now` forces the whole
`ToleranceController` impl to become `now`-aware **inherent** methods. **This is the same move R2 made
for EIR / `ResolutionEngine`** (see `eir.rs:176`), and it is a LABELED decision for DAP review — §3.

## 2. Task-by-task

### Task 1 — `produced_at` from a per-call `now`

`screen` now takes `now: Timestamp` and stamps `Ok(ScreenPass { version: self_set.version.clone(),
produced_at: now })`.

**I had to change `screen`'s signature** (added `now`, made it `pub`), and — because it is a core
trait method — that change removed it from the `ToleranceController` trait impl (§3). The value comes
from the evaluating call, never from stored state; the four-pattern held-clock grep is empty (§4).

**The version it supplies is correct, not a default.** `version: self_set.version.clone()` is the
`SelfSet` actually screened against, and it was **already matched against the live corpus** at the
method's first check (`if self.corpus.version() != self_set.version { return Err(FailsCentralTolerance) }`,
heimdall.rs), so a pass is only produced when the version genuinely names what was screened. The new
test (Task 4) asserts both the version and the `now`.

any other crate constructs one; `brokkr-adapt` does not exist. No sentinel change was needed for it.
Confirmed, not assumed.

## 3. The structural decision, labeled for DAP review

**`impl ToleranceController for Heimdall` is dropped; `grant`, `grant_heuristic`, `screen`, and
`host_harm` are now inherent methods on `Heimdall`, with `screen` taking `now`.**

This mirrors R2's EIR precedent verbatim (EIR dropped `impl ResolutionEngine` for the same reason; the
rationale doc lives at `eir.rs:176`). A doc block on the inherent impl (`heimdall.rs`) states the same
reasoning.

Two consequences, both handled and neither a weakening of a workspace-wide guarantee:

1. **The I-4 Deterministic refusal is preserved verbatim as an inherent `grant`.** Core's provided
   `grant` refused a `Deterministic` target with `NonSuppressibleGate`; the inherent `grant` does the
   identical match. **Core's `ToleranceController` trait, its sealed provided `grant`, and its I-4
   negative test (`brokkr-core/tests/negative_invariants.rs::test_i4`) are untouched** — the
   workspace-wide I-4 property (the core trait cannot be subverted) stands exactly as before. What
   changes is that HEIMDALL no longer *inherits* the refusal; it states it explicitly. The sentinel's
   own I-4/P-2 test (`test_oqgf_p_2_tolerance_refuses_deterministic_target`) exercises the inherent
   `grant` directly and passes.
2. **`grant_heuristic` is now a private inherent helper** (it was public only by virtue of being a
   trait method; nothing outside HEIMDALL calls it — grep-confirmed — and its sole caller is the
   inherent `grant`).

**Why not something lighter.** There is no way to keep the `ToleranceController` impl and give `screen`
a `now`: the trait mandates `screen`, the trait `screen` cannot carry `now`, and it cannot honestly
produce a `ScreenPass` with a real `produced_at` without one (a default or `Timestamp(0)` would be the
lie Task 1 forbids; a held field would be the I-13 defect). A trait cannot be partially implemented, so
the impl must go whole. This is precisely the producer-signature question R11 raised, now answered the
only way the scope lock permits.

**Why this is not a `§4` gap or a STOP.** R2 established and the DAP accepted this exact resolution for
EIR. It is a known, precedented, sentinel-scoped move, labeled here for review — not an
invented rule and not a blocked build.
