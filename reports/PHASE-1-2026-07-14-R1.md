## 2. Two builder decisions, surfaced for your ratification

Both are tightenings (they add constraint / remove surface); neither relaxes anything.
I flag them because you ratify the diff.

1. **Zero dependencies; hand-rolled errors instead of the pre-approved `thiserror`.**
   Error types implement `core::fmt::Display` + `core::error::Error` via a small local
   macro. This keeps the foundational crate `no_std` and dependency-free (strongest
   supply-chain posture) and needs no network to build. `thiserror` is pre-approved and
   expected by house style; I declined it here deliberately. If you prefer `thiserror`,
   say so and I will switch (it is a small change).
2. **`#![no_std] + alloc`, with two non-invariant-bearing shape substitutions:**
   `Timestamp(u64)` for `std::time::SystemTime`, `ResourcePath(String)` for
   `std::path::PathBuf`. This honors the architecture's "`no_std` where feasible"
   preference. Neither substituted type carries an invariant.

## 3. The crypto seam (as instructed)

`brokkr-core` defines cryptography as **traits** (`Signer`, `Verifier`, `Hasher`) and
holds **no implementation**. `DualSignature`, `Digest`, `Attestation`, `Signature`
carry opaque bytes plus a **typed** algorithm identifier (`SignatureAlg`, `HashAlg`,
`KemAlg` — never a string, OQGF-G-5). Nothing calls wolfCrypt. The negative tests run
against a **mock** signer/verifier/hasher (`tests/common/mod.rs`) — no FFI. Phase 2
(`brokkr-crypto`) implements these traits against wolfCrypt. `brokkr-core` has no
dependency on `brokkr-crypto` or any C library (I-5).
