**1.4 detail.** `map_intent_error` handles all six variants: `Attenuation(Expired)`→`ChainExpired`, `Attenuation(WouldBroaden)`/`RootSignatureInvalid`/`EntrySignatureInvalid`/`BrokenLink`→`ChainInvalid`, `HopKeyMissing`→`IdentityUnverified`, `Backend`→`ChainInvalid`. **Two arms are unreachable from SINDRI and correctly fail-closed:** `Backend` (produced only while *signing*; SINDRI only *verifies*) and `HopKeyMissing` (SINDRI resolves every key before calling `verify_chain_public`, never passing a short slice). ## 3. Findings (all LOW / informational)

### F-13 (LOW) — the replay-nonce map never evicts a `u64::MAX`-expiry chain
**Where:** `Orchestrator::check_guards`, `st.seen_nonces.retain(|_, expiry| now.0 <= expiry.0)`.
**Behavior:** a chain whose `expiry` is `u64::MAX` is retained forever (any `now ≤ MAX`), so its `(principal, nonce)` entry is permanent. Under sustained distinct-nonce, MAX-expiry chains, the map grows unbounded (a slow memory leak).
**Why LOW:** (a) `u64::MAX` expiry is itself a misconfiguration — OQGF-M-14 bounds a chain's expiry to the actor's credential lifetime, so a well-formed chain expires and its entry is evicted; (b) the growth is one small entry per *distinct* nonce, and the replay guard's whole purpose is to remember consumed nonces, so *some* retention is correct. **Recommendation:** cap accepted expiry at the guard (reject an implausibly far expiry), or bound the map with an LRU. Not a security hole — the failure mode is memory, and it is fail-safe (it never *forgets* a nonce, so it never wrongly permits a replay).

### F-14 (LOW) — `sanitize_for_audit` drops everything after an unterminated ANSI CSI
**Where:** `sanitize_for_audit`, the `\u{1b}` arm — on `ESC [`, it consumes chars until a CSI final byte (`@`–`~`); if none arrives (the string ends), it consumes the **rest of the string**.
**Behavior:** a rationale/detail beginning `\x1b[` with no terminator is sanitized to everything *before* the ESC — an attacker who controls the model's `rationale` can make the recorded rationale mostly empty by prefixing an unterminated CSI.
**Why LOW:** (a) the dropped content is the model's *untrusted* free text, not a governance decision (those are separate, structured audit events); (b) dropping is **fail-safe** — the alternative (recording the raw ESC) is the very log-injection F-8 exists to prevent; (c) the record still exists, dual-signed, with its structured fields intact. **Recommendation (optional):** cap the CSI-skip at a small bound (e.g. 16 chars) so a lone `ESC[` drops only a few bytes, not the tail. Named because a white-box attacker would find it.

### F-15 (LOW) — `SandboxedTool::resolve("")` accepts the sandbox root directory
**Where:** `SandboxedTool::resolve`; `root.join("")` normalizes to the root, which `starts_with(root)` → `Ok(root)`.
**Behavior:** an empty `detail` passes the sandbox check and returns the root *directory* path. The subsequent `std::fs::write(root, …)` would fail at the OS layer (cannot write a file to a directory), so no write occurs — but the **rejection comes from the filesystem, not the sandbox check**.
**Why LOW:** no escape (the path is the root, inside the sandbox) and no write (fs rejects a directory target). It is a defense-in-depth gap only: the sandbox check should arguably reject an empty/directory target itself. **Recommendation:** `resolve` rejects an empty `detail` (and, if desired, any path resolving to the root itself). Harmless today; tidier to reject early.

### F-16 (LOW, = 13B F-6 residual restated) — the parser's last-pair-wins lets a suffix control the action
**Where:** `parse_action` — the line loop overwrites `tool`/`path`, so the **last** `TOOL:`/`PATH:` pair wins.
**Behavior:** an attacker who controls the model's *output suffix* controls the extracted action, even if a benign pair appears first. Still gated by SINDRI (the result must be a declared, in-scope tool), so this is a *parser-ambiguity* residual, not a spine bypass — the same shape as 13B's finding, re-confirmed under white-box reading.
**Why LOW:** the spine gates whatever the parser produces; the residual is that the parser is permissive about *which* pair. **Recommendation:** reject a response containing *more than one* `TOOL:` line (ambiguous → `unknown` → deny), which is stricter and removes the suffix-control vector.

### F-17 (LOW/INFO) — `json_string_field` returns a partial value on a truncated string
**Where:** `json_string_field` — the value walk ends with `// Unterminated string — return what we have rather than fail. Some(out)`.
**Behavior:** a `response` field with no closing quote yields the partial contents rather than `None`. The partial text then flows to `parse_action` (which, on a truncated coding proposal, yields `unknown` → deny).
**Why LOW/INFO:** fail-safe downstream (a truncated proposal denies), and the design deliberately prefers a partial record over losing the whole response. **Recommendation (optional):** return `None` on an unterminated value so the backend surfaces a clean `BackendError` rather than a silent partial. Documented as a deliberate, safe behavior.

## 4. Confirmed-sound logic (the white-box "PASS" list)

- **SINDRI conjuncts** run in order with early exit; vacuous grants (empty caps / no-op invariant) are intended; `map_intent_error` is total and fail-closed on its two unreachable arms.
- **Strict parser** is fail-closed on every malformed input (empty value, homoglyph, escaped JSON, truncation) → `unknown` → deny.
- **FFI wrappers** turn every wolfSSL failure into a `TlsError`/`CryptoError` value; empty and large messages sign and verify; wrong-key verify fails; no panic, no UB reachable from the safe API.
- **Guard arithmetic** has no exploitable off-by-one: `saturating_sub` on the cutoff, strict-less monotonic, replay evaluated last and fail-safe.
- **Intent chain** verification is iterative (no recursion/stack risk), linear in hops, and correct at the boundaries (root-only, identical scope).
- **SandboxedTool** rejects absolute paths and `..` escapes; the two soft spots (in-root symlink, empty path) are documented and non-escaping.
