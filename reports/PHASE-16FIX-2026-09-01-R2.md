## 1. What changed

### F-33 — fail-closed `permissive()` (envelope validated before it governs)

`brokkr-core`: `CapabilityEnvelope::permissive()` now ends with a **hard** `assert!(validate().is_ok(), ..)` (release-active), replacing the R1 `debug_assert`. The library default is validated before it governs (I-14); an inconsistent construction panics **fail-closed** rather than governing with an invalid envelope.

### F-34 — egress matches host, port, AND protocol

`brokkr-core`: `Destination::Network` gains `port: u16` and `protocol: EgressProtocol`. `brokkr-cli` `check_egress` admits a network crossing only when host (normalized) **and** port **and** protocol all match a signed manifest rule; any mismatch is a `Denied`. Both canonical encoders (`brokkr-audit`, `brokkr-sentinel`) encode the new fields so the audit chain stays injective.

## 2. Two deviations from the DAP's literal spec — flagged for ratification

Both are **additive / correctness-preserving; neither relaxes any requirement.**

1. **`channel` retained.** The DAP's literal field list (`{ host: String, port, protocol }`) omitted `channel`. `channel: ChannelStrength` is **kept**, because HÚÐ's egress condition 8 (`brokkr-barrier` `huth.rs:145`) reads it for channel-strength-collapse enforcement — dropping it would regress a *different* deterministic gate, unrelated to F-34. F-34 adds port/protocol **alongside** channel.
2. **`host: Host` retained** (not `String`). `Host` is compared against `DestinationClass::Network { host: Host }` in `huth.rs:282` and encoded via `as_str()`; changing to `String` would ripple into `DestinationClass`, which the DAP did not direct changing. Comparison uses `as_str()`, so the host type is semantically irrelevant to the match.

Also: **`assert!` instead of `.expect()`** in `permissive()` — §6 denies `clippy::expect_used`/`unwrap_used` in production; `assert!` is the §6-clean way to get the identical hard, release-active panic the DAP directed. `Destination::Reasoner` is unchanged, as directed.
