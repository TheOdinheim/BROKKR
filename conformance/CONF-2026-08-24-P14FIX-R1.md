## OQGF-M-14 — chain freshness / no replay (F-13)

> "Intent Provenance Chains SHALL carry a freshness nonce and an expiry."

| Field | Content |
|---|---|
| Code path | The 13-FIX replay ledger (`Orchestrator::check_guards`) consumed a `(principal, nonce)` within its expiry. **F-13** bounds that ledger: `MAX_NONCE_ENTRIES = 10_000`; at capacity the smallest-expiry entry is evicted **after** the replay check and **before** inserting a genuinely-new nonce. A well-formed chain (bounded expiry, OQGF-M-14) is still evicted by expiry; a *malformed* far-expiry chain can no longer grow the ledger without bound. |
| Test | `fix_f13_nonce_ledger_bounded` (`brokkr-cli/tests/redteam_14fix.rs`). |
| Verdict | **strengthened.** Replay denial is unchanged for well-formed chains; the ledger is now memory-bounded and never preferentially forgets a still-fresh nonce, so it cannot wrongly admit a normal-chain replay. |

## OQGF-P-1 — host-harm bound / no over-denial / availability (F-13, F-15, F-16, F-19)

> "Disruption of a legitimate operation is a governance failure of equal standing to a missed threat."

| Field | Content |
|---|---|
| Code path | Every new guard is calibrated **not** to over-deny: **F-13** evicts only when at cap and only the entry nearest expiry, so a fresh chain is never blocked; **F-15** rejects only an *empty* path (never a valid write target), while a legitimate in-root path still resolves; **F-16** takes the *first* declared pair (the defender's benign choice), so a valid proposal still acts; **F-19**'s 10 MiB cap is far above any real model response. |
| Test | `fix_f13_nonce_ledger_bounded` (nonce_1 still replay-denied, nonce_0 re-admitted), `fix_f15_empty_detail_rejected` (`safe.txt` still `Ok`), `fix_f16_first_pair_wins`, `fix_f19_response_bound_exists_and_reasonable`. |
| Verdict | **satisfied.** Every new guard admits legitimate work; the fixes add safety without metastasizing into autoimmunity. |

## OQGF-R-1 — dual-family signing integrity (F-18)

> "…at least two PQC signature families … in parallel for any signature relied on for legal evidence."

| Field | Content |
|---|---|
| Code path | **F-18** adds a `sig_size()` cross-check to `SlhDsaShake192s::generate` (ffi.rs), symmetric with `MlDsa65::generate`: a wrong-parameter SLH-DSA key is rejected at keygen (`SLHDSA192S_SIG_SIZE = 16224`, the FIPS-205 *192s* size — the red-team report's 35664 was the *192f* variant). Signing and dual-family verification are unchanged; the SLH-DSA sign buffer was already library-sized, so this is defense-in-depth, not a memory fix. |
| Test | `fix_f18_slhdsa_sig_size_checked` (`brokkr-crypto/tests/redteam_14fix.rs`). |
| Verdict | **strengthened.** Both PQC families now detect a mis-parameterized key at construction; the hash-based half of the dual signature is size-verified symmetrically with the lattice half. |

## OQGF-A — audit integrity and reviewability (F-14, F-20)

> Organ 5 records are the accountability spine; a record must be trustworthy for review, and reconciliation must see what happened.

| Field | Content |
|---|---|
| Code path | **F-14** caps the audit sanitizer's CSI-skip at 16 chars, so an *unterminated* ANSI CSI can no longer truncate a recorded value's tail — an attacker prefixing a lone `ESC [` drops at most 16 bytes, not the remainder. The escape introducer is still dropped (F-8 render-safety preserved). **F-20** feeds HEIMDALL an `Observation::Hop { executed: None }` when an *authorized* action fails to execute, so the reconciliation loop (OQGF-M-12) sees an authorized-but-failed execution rather than being blind to it. |
| Test | `fix_f14_unterminated_csi_bounded`, `fix_f14_terminated_csi_still_stripped`, `fix_f20_tool_failure_observed`; 14C `attack_5_1_tool_error_is_observed_by_heimdall` (updated from the F-20-documenting negative). |
| Verdict | **strengthened.** Audit records resist tail-truncation; the reconciliation loop is no longer blind to a failed authorized execution. |

## OQGF-M-12 — cross-hop reconciliation completeness (F-20)

> "The action actually executed at each hop SHALL be reconciled against … the Root Intent."

| Field | Content |
|---|---|
| Code path | Before F-20, a tool `Err` returned `HopResult::Error` before the step-8 reconciliation feed — a failed authorized execution was invisible to HEIMDALL. F-20 emits `Observation::Hop { executed: None }` on that path, making authorized-but-failing tools detectable as a pattern. |
| Test | `fix_f20_tool_failure_observed`; 14C `attack_5_1_...`. |
| Verdict | **strengthened.** Reconciliation now observes execution *failures*, not only successes and denials. (Live reconciliation remains post-executor, per §6.7 — unchanged.) |

## Prime directive §2 / invariants I-1, I-12, I-13

| Field | Content |
|---|---|

## Findings

**Zero requirements ABSENT. Zero verdicts moved backward.** This is a hardening phase: it bounds or enforces defenses that were documented residuals (F-13 ledger growth, F-14 audit truncation, F-15 empty target, F-19 unbounded read) and closes low-severity gaps (F-16 suffix-control, F-17 partial-value leak, F-18 signer asymmetry, F-20 reconciliation blindness), each with a regression test that fails without the fix.

**Three findings accepted with no code change**, documented rather than latent: **F-11** (the guarantee is a private minter, not a sealed trait — the committed doctests already describe the real, stronger mechanism); **F-12** (`forbid(unsafe_code)` is a crate attribute a doctest does not inherit — the transmute doctest already carries it); **F-21** (timing side channels are inherent to variable-cost cryptographic work — equalizing them would waste resources and the observer is the trusted driver, not the model). None is actionable without cost exceeding benefit; each is named in `reports/PHASE-14FIX-2026-08-24-R1.md` §1.

**One honest boundary, unchanged and named:** F-16's first-pair rule and F-17's fail-closed truncation are *parser* hardenings; whatever the parser produces is still gated by SINDRI — the parser is not the spine, and these shrink its ambiguity rather than replace the gate.
