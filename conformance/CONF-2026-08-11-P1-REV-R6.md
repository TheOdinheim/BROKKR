## 1. OQGF-P-1 — the host-harm bound (AMD-002)

> *"A conforming system SHALL define host harm … SHALL continuously measure its host-harm rate, and SHALL
> keep that rate within a declared, documented bound. Disruption of a legitimate operation is a governance
> failure of equal standing to a missed threat; it SHALL be tracked, reported, and reviewed with the same
> rigor applied to a false negative."*

| Aspect | Placed here? | Where it lands |
|---|---|---|
| **Definition** of host harm — a defensive response applied to legitimate work | **Yes** — `DefensiveResponse{Anergy,Deny,Quarantine,Throttle}` names the four §6.7 responses; `HostHarmIncident` binds the response to the `Action` harmed | this revision |
| **Numerator** — a *confirmed* host-harm incident | **Yes (type)** — `HostHarmIncident{response,action,confirmed_by,at}`; `confirmed_by: Dap` required (an unconfirmed report is not representable) | this revision |
| **Rate** — numerator / governed actions evaluated in the window | **No** | `brokkr-sentinel` (HEIMDALL, Phase 8) |
| **Bound comparison** and **continuous measurement** | **No** | Phase 8 |

**Verdict: PARTIAL.** The numerator's *type* is placed (`HostHarmReport` — the rate/bound container — was
already present from Phase 1); the rate, the bound comparison, and continuous measurement are Phase 8.
**Not claimed satisfied.** Proof: the types compile and re-export (`cargo test -p brokkr-core`); no logic is
asserted because none is built.

## 2. OQGF-P-5 — autoimmunity and storm detection (AMD-002)

> *"(a) autoimmunity — a sustained rise in host-harm rate above the declared bound; and (b) response storm —
> any single graded response whose magnitude exceeds a declared host-availability threshold."*

- **P-5a (autoimmunity):** needs the **rate** (§1) and a sustained-breach determination — both Phase 8.
  `HostHarmReport.autoimmunity: bool` (Phase 1) is the field the Phase-8 monitor will set; this revision
  supplies the numerator type that feeds the rate, nothing more.
- **P-5b (storm):** needs a **declared blast radius** to measure a response against (§6.7: "Undeclared, the
  bound cannot be exceeded and P-5b is unenforceable"). Neither the blast-radius declaration nor the
  magnitude comparison is placed here; `StormEvent` (Phase 1) is the container the Phase-8 monitor emits.

**Verdict: traced, not advanced by this revision.** No P-5 obligation is satisfied or newly placed here;
the host-harm numerator this revision adds is shared machinery P-5a will consume at Phase 8. **0 absent** —
P-5 is correctly a Phase-8 obligation, recorded rather than silently skipped.

## 3. OQGF-P-6.1 / P-6.3 — the learning gates (AMD-003)

> **P-6.1:** *"A Refined Detector MAY be generated only from a Seeding Incident — a DAP-confirmed true
> positive …"* — **P-6.3:** *"A refinement that improves detection but raises host harm above the declared
> bound SHALL be discarded regardless of its detection gains."*

- **P-6.1 (the mirror):** `HostHarmIncident` is the deliberate counterpart of `adapt.rs::SeedingIncident`.
  Both encode that confirmation is a **human act** — a true positive seeds learning, a false positive counts
  toward host harm, and neither is derivable from the action alone. The symmetry is now expressed in the
  type surface; `SeedingIncident` (P-6.1) is unchanged and satisfied-in-shape from Phase 1.
- **P-6.3:** KVASIR's "discarded regardless of detection gains if it raises host harm above the bound" now
  has a **countable numerator** (`HostHarmIncident`) to build the bound comparison over — but the comparison
  itself is Phase 8 (the rate) / Phase 9 (the KVASIR activation gate). **Traced; not placed here.**

**Verdict: traced.** No backward movement; the P-6.1 mirror is a clarity gain, not a re-scoping.
