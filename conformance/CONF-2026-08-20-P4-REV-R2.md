## OQGF-M-11 — The Costimulation Gate (four conjuncts)

> "No actor SHALL be granted privileged action on the basis of identity attestation (Signal 1) alone. A privileged action SHALL require both a valid identity attestation per OQGF-M-1 and a valid Intent Provenance Chain per OQGF-M-8 (Signal 2). An actor presenting valid identity with absent, malformed, or invariant-violating intent provenance SHALL be placed in architectural anergy: all privileged action denied."

OQGF-M-11 requires **four** conjuncts for a grant (BROKKR-ARCH §6.4): Signal 1, Signal 2, action-in-scope, action-respects-invariants. Phase 4 (Rev 1.3) enforced the two cryptographic ones and recorded M-11 **PARTIAL** pending the other two.

| Field | Content |
|---|---|
| Code path | `Sindri::evaluate`: `signal_1` → `signal_2` → **conjunct 3** (`genome_resolver.resolve_tool(&action.tool)` → `OutOfScope` if absent; every `required_capabilities` entry must be in `chain.current_scope().capabilities()`, else `OutOfScope`) → **conjunct 4** (each `chain.current_invariants()` invariant `resolve_invariant`'d → `InvariantViolated` if no predicate; `InvariantViolated` if the tool requires a `forbids_capabilities` entry or carries a `forbids_privilege` class). Both new conjuncts read genome data through the `GenomeResolver` seam (the `KeyResolver` pattern), never the full genome. |
| Test (fails if removed) | conjunct 3: `tool_not_in_genome_yields_out_of_scope`, `tool_capability_missing_from_scope` (→ `OutOfScope`); conjunct 4: `invariant_with_no_predicate_yields_violated`, `tool_requires_forbidden_capability`, `tool_has_forbidden_privilege`, `multiple_invariants_second_fails` (→ `InvariantViolated`); grants when all four hold: `tool_all_capabilities_in_scope_no_invariants`, `tool_passes_all_invariants`, `multiple_invariants_all_pass`. Removing conjunct 3 or 4 would flip each negative to `Granted`. |
| Verdict | **PARTIAL → satisfied (forward move, §5.3).** All four conjuncts are now enforced by `evaluate`, in the §6.4 flowchart order. The Deferred-Conjunct Deadline's precondition on Phase 11 is met (the executor may now be wired to a gate that evaluates the action against scope and invariants). |

## OQGF-M-10 — Intent Invariant Enforcement

> "The Root Intent SHALL carry an invariant set. Every hop SHALL evaluate the current action against the invariant set before acting, independent of any reframing that has occurred upstream. Invariants are themselves subject to monotonic attenuation: a hop MAY add invariants but SHALL NOT remove or weaken an invariant present in the chain."

| Field | Content |
|---|---|
| Code path | Accumulation and non-removal are SKULD's (unchanged). The **evaluation of the current action against the invariant set** — the clause previously recorded PARTIAL as "not yet performed anywhere" — is now conjunct 4 in `Sindri::evaluate`. |
| Test (fails if removed) | `tool_requires_forbidden_capability`, `tool_has_forbidden_privilege`, `multiple_invariants_second_fails`, `invariant_with_no_predicate_yields_violated`. |
| Verdict | **action-evaluation clause: PARTIAL → satisfied for declarative invariants (forward move).** See the residual below — invariants requiring interpretation of `Action.detail` are still not evaluated, and that half remains PARTIAL. |

### Residual (recorded honestly, §13 — unchanged by this revision)

Conjunct 4 evaluates the **declarative** invariant predicates (`forbids_capabilities`, `forbids_privilege`), computable from the genome. An invariant that requires interpreting `Action.detail` — a path rule such as *read-only outside ./src*, or a content rule such as *no secret material in committed output* — is **not** expressible as these predicates and is **not** evaluated. This is the §13 detail-level-invariant residual (the open half of RISK-2026-0004). This revision does not close it and does not claim to; the fail-closed backstop (an invariant with no resolvable predicate → `InvariantViolated`) means such an invariant, if declared without a predicate, denies rather than passes.

## Structural invariants

- **I-1** — SINDRI still mints nothing: `evaluate` returns `Result<(), AnergyReason>`, and the provided `authorize` (untouched) is the sole minter of `AuthorizedAction`. The two new conjuncts only add **deny** paths (`OutOfScope`/`InvariantViolated`); the worst a buggy conjunct can do is wrongly deny. **Satisfied.**
- **I-13** — `now` is still a per-call parameter threaded to the freshness check; the new conjuncts evaluate no time and hold no clock. Held-clock grep empty. **Satisfied.**
- **I-5** — `brokkr-gate` gains **no** dependency: the `GenomeResolver` projection keeps `ToolEntry`/`InvariantEntry` out of the gate (production backs the seam from the genome). Deps remain `brokkr-core`, `brokkr-intent`, `brokkr-crypto`. **Satisfied.**
