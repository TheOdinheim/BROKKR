## 0. Why R2 exists

DAP review found a Section 5.3 defect in R1's *proofs* (not its encodings): the
compile-fail doctests used a bare ` ```compile_fail `, which passes if the code fails
to compile for **any** reason. A compile-fail test that could pass for the wrong
reason is not a proof — it is the "test grading itself" failure. R2 pins the exact
error code on every compile-fail doctest and closes the I-1 proof gap. The invariant
*encodings* were accepted in R1 review and are unchanged.

## 1. Every compile-fail doctest now pins its error code

Pinning is a real test: `rustdoc` fails the doctest unless the compiler emits the
named error code. **All ten still pass after pinning** — which proves each was already
failing for the intended reason. Had any been passing for an unrelated reason (e.g., a
type-inference failure `E0282` in the `any::<T>()` helper instead of the intended
`E0308`), pinning would have turned it red. None did.

| Doctest (file : item) | Invariant | Pinned code | Meaning | Pass |
|---|---|---|---|---|
| `gate.rs : AuthorizedAction` (literal) | I-1 | **E0616** | field `action` is private | ok |
| `gate.rs : AuthorizedAction` (`mint`) | I-1 | **E0624** | associated fn `mint` is private | ok |
| `gate.rs : AuthorizedAction` (`clone`) | I-1 | **E0599** | no method `clone` (type is not `Clone`) | ok |
| `barrier.rs : BarrierVerdict` | I-2 | **E0599** | no method `into_allow` | ok |
| `resolution.rs : EscalationType` | I-8 | **E0308** | `None` ≠ `BaselinePosture` | ok |
| `resolution.rs : ResolutionDecision` | I-8 | **E0308** | `None` ≠ `Dap` | ok |
| `genome.rs : ModelEndpoint` | I-11 | **E0308** | `None` ≠ `ClientCertRef` | ok |

The four `E0308` cases were the ones most at risk of the wrong-reason failure (the
`any::<T>()` helper). Pinning `E0308` confirms the mismatch is the *first and only*
error rustc reports: each `any()` infers cleanly from its concrete parameter position,
so the sole error is the `None` at the intended argument.

## 2. The I-1 gap, closed

R1's two I-1 doctests proved you cannot literal-construct `AuthorizedAction` and cannot
call `mint` from outside. They did **not** prove the actual invariant: *no `pub fn` in
the crate returns an `AuthorizedAction` except through `CostimulationGate::authorize`.*
R2 closes this three ways.

**(a) Source audit of `gate.rs` (independently verifiable by grep).**

- **`pub fn`s returning `AuthorizedAction` by value: none.** `grep -nE 'fn
  [a-z_]+\(.*\).*AuthorizedAction' brokkr-core/src/gate.rs` returns nothing. The type
  name appears in a function *return position* only inside
  `AuthorizationDecision::Granted(AuthorizedAction::mint(action))` (line 125).
- **The sole minter is `fn mint` (line 82) — private** (no `pub`), returning `Self`.
- **`mint`'s sole call site is line 125, inside the provided `authorize`.** `grep -nE
  'fn mint|AuthorizedAction::mint'` shows exactly: the definition (82) and that one
  call (125). (Line 54 is a doctest comment, not code.)
- Therefore the only value-producing path to an `AuthorizedAction` anywhere in the
  crate is `authorize` → `mint`. `authorize` is a provided trait method defined in
  core; an implementor overriding it still cannot call the private `mint`, so an
  override can only ever yield `Anergy` (fail-safe).

**(b) `AuthorizedAction` derives nothing** (confirmed: no `#[derive]` precedes `pub
struct AuthorizedAction`). It is neither `Clone` nor `Copy`, so a granted authorization
cannot be duplicated outside the gate — a caller cannot fan one grant into several. A
new `compile_fail,E0599` doctest proves `.clone()` does not exist even after obtaining
one by the sanctioned path. **No derive was removed** (there was none to remove); the
absence is intentional and now tested.

**(c) New runtime test** `test_i1_authorize_is_sole_construction_path`
(`tests/negative_invariants.rs`) obtains an `AuthorizedAction` via `authorize`
(Granted), reads it, and confirms a denying gate yields `Anergy` with no
`AuthorizedAction` at all.

## 3. Verification (evidence, reproduce with `cargo test --locked -p brokkr-core`)

- **Runtime tests: 12 passed, 0 failed** (was 11 in R1; +`test_i1_authorize_is_sole_construction_path`).
- **Doctests: 10 passed, 0 failed** (was 9 in R1; +the I-1 no-`clone` proof), every one now carrying its pinned error code.
- clippy (with the §6 deny lints) clean on the library; rustfmt clean.

The corpus enumeration, the requirement-by-requirement verdicts (0 absent, 11
