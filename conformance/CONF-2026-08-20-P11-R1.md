# Conformance Check — Phase 11 (brokkr-cli / the Orchestrator)

**Record ID:** CONF-2026-08-20-P11-R1
**Date:** 2026-08-20
**Scope:** `brokkr-cli` — the composition of the governed action cycle (BROKKR-ARCH §5). The orchestrator **enforces no requirement itself**; it composes the subsystems that do, in the order §5 specifies, with a deny-at-any-gate short-circuit. This check therefore records the **wiring** properties: that the composition routes every action through the gates, never executes without an `AuthorizedAction`, feeds reconciliation the executed action, and records decisions to SAGA.
**Enumerated from the corpus** (not the traceability table): the prime directive (§2), OQGF-M-11, OQGF-M-12, OQGF-A-1, OQGF-I-13 (quoted below), plus invariants I-1, I-5, I-12, I-13. Corpus is OQGF-1.0 + AMD-001…AMD-009.
**Author:** Claude Code (builder).
**Per RISK-2026-0007:** each item names the code path and the test that would fail if the check were removed.
**Zero requirements ABSENT.** No §4 gap. Where the orchestrator supplies only the wiring and a production backend supplies the rest, the verdict is **satisfied-at-composition with the residual named** — never claimed complete.

## What was checked, and against what

`brokkr-cli`'s `execute_hop` after this phase, against the quoted requirements, with test-double spies (no production backend). The doubles let each gate be made to deny in isolation, so the short-circuit and the recording are observable.

## Prime directive (BROKKR-ARCH §2) — the model is never in the trust path

> "The model proposes; the deterministic spine disposes. The reasoning model is never in the trust path for any decision to block, permit, raise, or lower posture."

| Field | Content |
|---|---|
| Code path | `execute_hop`: `reasoner.propose(...)` returns a `Proposal` whose `action` is **untrusted input** to the spine. The action then passes REGIN (`genome.check`), SINDRI (`gate.authorize`), and HÚÐ (`barrier.evaluate`) before `tool.execute`. The reasoner is consulted for a proposal and **never** for a verdict — no gate reads the proposal's `rationale`, and no `HopResult` path consults the reasoner after step 3. |
| Test (fails if removed) | `gate_denial_stops_execution`, `barrier_denial_stops_after_gate`, `genome_refusal_stops_before_gate` — the proposal is produced, then a downstream gate denies and the tool never runs. If the orchestrator executed on the proposal alone (model in the trust path), these would execute. |
| Verdict | **satisfied (wiring).** Every action the reasoner proposes is disposed by the deterministic gates; the model's output is a proposal, not a command. |

## OQGF-M-11 — the costimulation gate (composition)

> "No actor SHALL be granted privileged action on the basis of identity attestation (Signal 1) alone… An actor presenting valid identity with absent, malformed, or invariant-violating intent provenance SHALL be placed in architectural anergy: all privileged action denied."

| Field | Content |
|---|---|
| Code path | The orchestrator obtains an `AuthorizedAction` **only** from `gate.authorize(&identity, &chain, action, now)`'s `Granted` arm and hands that exact value to `tool.execute`. It never constructs one (I-1). On `Anergy` it records the anergic authorization, observes it, and returns `Denied{Gate}` without executing. SINDRI itself enforces the four conjuncts (Phase-4 rev, commit `884958f`); the orchestrator enforces that **nothing executes but a gate-minted authorization.** |
| Test (fails if removed) | `full_cycle_executes_on_all_gates_clear` (executes only when the gate grants) and `gate_denial_stops_execution` (anergy → tool count 0). Removing the gate call, or executing on the raw action, flips these. |
| Verdict | **satisfied (wiring).** M-11 is *enforced* by SINDRI; the orchestrator *routes every tool call through it* and admits no other path to the executor. |

## OQGF-M-12 — cross-hop behavioral reconciliation

> "The action actually executed at each hop SHALL be reconciled against both the intent declared at that hop and the Root Intent."

| Field | Content |
|---|---|
| Code path | After `tool.execute`, `execute_hop` feeds `sentinel.observe(&Observation::Hop { authorized: action, executed: Some(action) }, now)`. **This is the first point in the whole system where `executed` is `Some(..)`** — Phase 8 built the reconciliation mechanism with `executed: None` (no executor existed); Phase 11 supplies the live executed action (BROKKR-ARCH §6.7, Rev 1.11: "the live stream begins at Phase 11"). |
| Test (fails if removed) | `heimdall_receives_hop_observation_with_executed` — asserts the observations contain a `Hop { executed: Some(_) }`. Removing the step-8 reconciliation feed drops it. |
| Verdict | **satisfied-at-wiring; the M-6 reconciliation *statistic* remains PARTIAL** (unchanged). The orchestrator now delivers real executed actions to HEIMDALL; a per-supplier reconciliation pass rate (OQGF-M-6's fifth factor) is a statistic over many such outcomes against a real reasoner, still not produced (BROKKR-ARCH §13, unchanged). The mechanism is fed; the number is not yet computed. |

## OQGF-A-1 — decision records (the AI/ML decision)

> "For every regulated AI/ML decision the system SHALL record: the model identifier and version, the AIBOM digest, the input (or a privacy-preserving derivative thereof), the output, the explanation artifact, the timestamp, and the DAP."

| Field | Content |
|---|---|
| Code path | `execute_hop` records `AuditEvent::Proposal(ProposalRecord{ model, aibom_digest, input: RecordedInput::Derivative(sha384(payload)), output, explanation })` with the header `dap` and `now`. **The MÍMIR proposal is the one AI/ML decision in BROKKR** (§6.9); the deterministic-gate verdicts recorded alongside carry the header + their own payload, correctly, because no model made them. The input is a **privacy-preserving derivative** (SHA-384 of the cleared payload), never the payload itself. |
| Test (fails if removed) | `full_cycle_executes_on_all_gates_clear` and `saga_records_every_decision` — assert a `Proposal` event is present. Removing the record drops it. |
| Verdict | **satisfied for input-derivative/output/explanation/timestamp/DAP; PARTIAL for model identity and AIBOM digest.** `model.version`/`model.provider` are empty and `aibom_digest` is an empty placeholder — production sources them from REGIN's signed AIBOM (§6.2). Named, not hidden: the orchestrator records the derivative and the DAP faithfully; the model-identity fields await the production AIBOM wiring. |

## OQGF-I-13 — barrier decisions recorded

> "Every Barrier decision — a crossing allowed, denied, or quarantined, in either direction — SHALL be recorded in Organ 5 with the BCR digest or a record of its absence, the classification, the destination or origin, the deciding policy, and, where applicable, the accountable DAP."

| Field | Content |
|---|---|
| Code path | On a **blocked** reasoner crossing or a **blocked** action crossing, `execute_hop` records `AuditEvent::BarrierCrossing(BarrierCrossing{ verdict, flow, bcr_digest, dap })`. On a **cleared** reasoner crossing, `clear` returns `Ok(ClearedContext)` and does not hand back the `Allow`/`AcceptedRisk` verdict (it is the sole minter, evaluating once); the orchestrator therefore does not fabricate an `Allow` record — but a `Proposal` event exists **iff** the crossing cleared, so the allowed crossing is implicitly recorded by the proposal's presence. |
| Test (fails if removed) | `barrier_denial_stops_after_gate` and `bifrost_denial_stops_before_reasoner` exercise the blocked-crossing recording and short-circuit paths. |
| Verdict | **PARTIAL — blocked crossings recorded; explicit allowed-crossing records are SAGA/production.** The full "record every allowed crossing with the deciding policy" obligation is Organ 5's, exercised through production wiring; recording an `Allow` here would require either a second barrier evaluation or a fabricated verdict (neither honest). The blocked decisions are recorded, and the allowed crossing is implied by the proposal. Named, not hidden. |

## Structural invariants

- **I-1** — the orchestrator constructs no `AuthorizedAction`. It receives one only from `gate.authorize`'s `Granted` arm and passes that exact value to `tool.execute`; there is no other executor path. **Satisfied.** (Proof: `full_cycle_executes_on_all_gates_clear` executes only via the granted path; `AuthorizedAction` has no public constructor, so the code could not compile otherwise.)
- **I-5 / I-6 / I-9** — `brokkr-cli` is the workspace **leaf**: `cargo tree --workspace -i brokkr-cli` shows only itself; nothing depends on it. It is the composition root permitted to depend on `brokkr-reasoner`, `brokkr-tools`, and every governance crate — because nothing governs it. The one-way direction the governance crates rely on is intact. **Satisfied.**
- **I-12** — `Reasoner::propose` is reached only through a `ClearedContext` from `clear`; a BIFRÖST deny returns before the reasoner is consulted. **Satisfied.** (Proof: `bifrost_denial_stops_before_reasoner` — reasoner call count 0 on deny.)
- **I-13** — `now` is a parameter of `execute_hop` and of every subsystem call it makes; the `Orchestrator` struct holds no clock field. `Orchestrator::now()` is the single §4 wall-clock read and stores nothing. Held-clock grep over `brokkr-cli/src` matches only that reader. **Satisfied.** (Proof: `now_is_passed_not_held` — two hops with different `now`, each subsystem consulted twice, nothing cached.)

## Findings

**Zero requirements ABSENT.** No §4 gap. The orchestrator is composition, not enforcement: it satisfies the **wiring** obligations (route every action through the gates, execute only a gate-minted authorization, feed reconciliation the executed action, record decisions to SAGA) and defers the enforcement to the subsystems that own it. Three verdicts are **PARTIAL with the residual named** — OQGF-M-6's reconciliation statistic (mechanism fed, number not yet computed), OQGF-A-1's model-identity/AIBOM fields (placeholders pending production AIBOM wiring), and OQGF-I-13's explicit allowed-crossing records (blocked recorded; allowed implied by the proposal). Each residual is a production-wiring concern stated here, not a gate that was skipped. The prime directive, M-11 routing, M-12 live reconciliation feed, and invariants I-1/I-5/I-12/I-13 are **satisfied at the composition**, each with a named test that fails if the wiring is removed.
