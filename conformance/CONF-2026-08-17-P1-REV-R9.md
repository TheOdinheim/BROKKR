## 1. AMD-007 — OQGF-I-9 (Boundary Custody Record) and OQGF-I-10 (egress, deterministic)

> **I-9:** *"Data authorized to cross a Controlled Boundary above the Public classification SHALL carry, or
> be matched at the Barrier to, a signed Boundary Custody Record…"* — **I-10:** *"Data of a declared
> classification above Public SHALL NOT cross a Controlled Boundary to a destination not authorized for that
> classification. Absent a valid BCR authorizing the crossing, the Barrier SHALL deny it."*

| Aspect | Placed here? | Where enforcement lands |
|---|---|---|
| The `Context` carries a **declared `classification`** the egress gate decides on | **Yes** — `Context.classification` | this revision |
| The `Context` carries a **`bcr`** (required above Public, `None` for Public) | **Yes** — `Context.bcr` | this revision |
| The `Context` carries a **`datum`** so a BCR can be matched to it, and a **`personal`** tag | **Yes** — `Context.{datum, personal}` | this revision |
| Build a `BoundaryFlow::Egress` from the context, call the barrier, issue/verify the BCR, Deny above effective authorization | **No** | Phase 8.5 (BIFRÖST) |

**Verdict: type surface placed; I-9 and I-10 NOT claimed satisfied.** The four fields are exactly what
`BoundaryFlow::Egress` needs minus the destination (the reasoner endpoint, passed to `clear`), so §6.6's
*"the wire"* now has its facts. But no code in this revision builds a flow, calls the barrier, or issues a
BCR. Proof the surface is present and correct: `brokkr-core` builds and its I-12 test (which constructs a
full `Context` and clears it) passes.

## 2. AMD-007 — OQGF-I-12 (content inference is Heuristic; the deterministic gate does not consume it)

> *"Content inference — judging whether *unlabeled* data is sensitive — is a **Heuristic Response**… The
> heuristic sentinel is a backstop to, never a replacement for, the deterministic enforcement of declared
> classification."*

**Verdict: confirmed structurally — no derivation from payload.** `Context.classification` is a **declared**
field, set by whoever assembled the context. **No code in this revision reads `Context.payload`** to infer a
classification (grep: `payload` is read only by the existing `ClearedContext::get`/test assertions, never to
compute `classification`). The deterministic gate's input (the declared classification) is therefore never
taken from a heuristic source, which is exactly what I-12 requires. The content sentinel remains a Phase-8
backstop (HEIMDALL), not the gate's input.

## 3. AMD-009 — OQGF-P-11.1 (personal data as a governed, orthogonal dimension)

> *"…a Personal-Data Tag: a Data Classification dimension that composes with, and is orthogonal to, the
> sensitivity tier… including where that tier is Public."*

**Verdict: traced — now representable for the reasoner crossing.** `Context.personal:
Option<PersonalDataTag>` is orthogonal to `Context.classification` (a separate `Option`, not a tier of it),
so a **Public *and* personal** reasoner-bound context is representable and travels with the context. Phase
8.5's egress evaluation will therefore not short-circuit a Public personal context (the Rev 1.7 defect,
already corrected on the flow, is now expressible on the reasoner path too). Enforcement is Phase 8.5.
