## OQGF-M-5 — mutual authentication; one-sided TLS SHALL NOT satisfy

> "Mutual authentication SHALL be required for every connection; one-sided TLS SHALL NOT satisfy this requirement."

| Field | Content |
|---|---|
| Code path | `brokkr_crypto::TlsClient::connect` calls `wolfSSL_CTX_use_certificate_file` + `wolfSSL_CTX_use_PrivateKey_file` (present the client cert) **and** `wolfSSL_CTX_load_verify_locations` (verify the server against the CA). The gateway is configured `ssl_verify_client on`, so a connection **without** a client cert is rejected. |
| Evidence (fails otherwise) | The live handshake succeeds only *with* the client cert; a `curl` without `--cert` to the same gateway returns `400 No required SSL certificate was sent` (recorded in Step 0). The `tls_smoke` and `live_model` tests complete a real mutual-TLS 1.3 handshake. And I-11 keeps the type-level guarantee: `ModelEndpoint::client_cert` is a required field. |
| Verdict | **satisfied — real mutual TLS** (the type-level M-5/I-11 guarantee is now backed by a real mutual-auth handshake). |

## OQGF-I-1 / I-2 — HNDL sentinel; the negotiated channel is read, not assumed

> I-1: "…capable of identifying classical key exchange … and emitting an HNDL risk event." I-2: "…before that date, [classical-only TLS for data above Public] SHALL be treated as a graded risk event according to the HNDL risk score."

| Field | Content |
|---|---|
| Code path | `TlsClient::negotiated_group` reads `wolfSSL_get_curve_name` from the **live** session; `brokkr_bifrost::map_group` projects it to a `NamedGroup`; `Negotiated::strength` derives the `ChannelStrength`. BIFRÖST's committed clearance then collapses the endpoint's effective authorization to `min(ceiling, channel.permits())` via HÚÐ — a classical channel caps at Public. |
| Evidence (fails otherwise) | `live_model` logs `raw="SECP256R1" -> NamedGroup=Secp384r1 -> strength=Classical`. The **actually negotiated** group is read (a fact, not an offer). A Public context clears; an above-Public context over this classical channel would be denied by HÚÐ's condition 8 (built and tested in Phase 6/8.5). |
| Verdict | **satisfied for the deterministic half (real channel readback + effective-auth collapse); the graded HNDL *risk-event emission* is not newly exercised here** — the live test uses a Public context (which clears), so no above-Public denial or risk-event is raised. The emission path is the §11 A.6.1 trigger / HEIMDALL graded-response wiring, unchanged. Named, not hidden. |

## Code-standard conformance (CLAUDE.md §6)

- **`unsafe` confinement** — the TLS FFI lives in `brokkr-crypto` only (its second confined `unsafe` module, `tls.rs`, every block with a SAFETY note). `brokkr-bifrost` and `brokkr-reasoner` contain **no** `unsafe` and keep `#![forbid(unsafe_code)]`. This is why Option A (FFI in bifrost) was rejected — §6 forbids it and `links = "wolfssl"` collides. **Satisfied.**
- **No new external dependency** — MÍMIR's HTTP/JSON is manual; no crate was added (a §6 supply-chain decision avoided). **Satisfied.**
- **No panics in production paths** — the new modules use no `unwrap`/`expect`/`panic`/indexing; clippy's `deny` set passes across the workspace. **Satisfied.**
