## OQGF-P-12.1 / P-12.2 — Envelope validity (F-33) — PARTIAL → **satisfied for the default**

> "A system whose capabilities are not inventoried, not signed, and not assessed for tier determination does not satisfy this requirement."

| Field | Content |
|---|---|
| Code path | `brokkr-core` `CapabilityEnvelope::permissive()` now ends with a **hard** `assert!(validate().is_ok(), ..)` — a release-active panic, not `debug_assert` (F-33, DAP-directed). The library-provided default is validated before it governs (I-14): if the construction were ever made inconsistent, it panics **fail-closed** (no invalid envelope is returned) rather than silently governing with one. |
| Deviation | The DAP directed `validate().unwrap()` / `.expect()`. **`assert!` is used instead** — §6 denies `clippy::unwrap_used` / `expect_used` in production, and `assert!` gives the identical hard, release-active panic without an `#[allow]`. Same behaviour, §6-clean. Flagged for ratification; relaxes nothing. |
| Test | `redteam_16::fix_permissive_validates`; the `assert!` itself runs in every build (release too). |
| Verdict | **satisfied for the library default.** The residual is now only F-32 (a *caller-supplied* envelope via `with_envelope` is still not validated at the boundary) — a documented caller-contract the DAP did not direct changing, and a narrower residual than the prior fail-open-default. Recorded PARTIAL→satisfied for the default; F-32 stands as the remaining, narrower item. |

## OQGF-P-12.4 — Deterministic egress: host, port, AND protocol (F-34) — PARTIAL → **satisfied**

> "all outbound network traffic SHALL be denied unless the destination, protocol, and port are listed in a signed egress manifest."

| Field | Content |
|---|---|
| Core type | `brokkr-core::barrier::Destination::Network` gains `port: u16` and `protocol: EgressProtocol` (DAP-directed). Both canonical encoders (`brokkr-audit`, `brokkr-sentinel` `write_destination`) now encode them, so the signed content stays injective over the type's fields. |
| Code path | `brokkr-cli` `check_egress` now destructures `{ host, port, protocol, .. }` and admits a crossing only when host (normalized, Fix 2) **and** `port` **and** `protocol` all match a manifest rule; a mismatch on any of the three is a `Denied`. |
| Deviations (2) | **(1)** The DAP's literal field list was `{ host: String, port, protocol }`, omitting `channel`. **`channel: ChannelStrength` is retained**, because HÚÐ's egress condition 8 (`brokkr-barrier` `huth.rs:145`) reads it for channel-strength-collapse — dropping it would regress a different deterministic gate. F-34 **adds** port/protocol alongside channel; it does not replace it. **(2)** `host` stays `Host` (not `String`) — `Host` is compared against `DestinationClass::Network { host: Host }` in `huth.rs:282` and encoded via `as_str()`; `String` would ripple into `DestinationClass` (which the DAP did not direct changing). Both deviations are additive / correctness-preserving; **neither relaxes any requirement.** Flagged for ratification. |
| Test | `redteam_16::fix_egress_all_three_match_allowed` (all three match → admitted), `fix_egress_port_mismatch_denied` (port 8444 ≠ 8443 → denied), `fix_egress_protocol_mismatch_denied` (HTTP ≠ HTTPS → denied), plus the Fix-2 host tests. `Destination::Reasoner` is unchanged (the BIFRÖST crossing, as the DAP directed). |
| Verdict | **satisfied.** The manifest's `port` and `protocol` — dead before (F-34) — are now enforced. A `#[non_exhaustive]` catch-all in the protocol encoder (tag 0 for a future variant) is the one place the "no catch-all" canonical discipline cannot be kept; documented in both encoders, harmless today (Network destinations are not recorded). |
