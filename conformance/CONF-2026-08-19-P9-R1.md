## OQGF-P-6.1 — Incident-Seeded Refinement

> "A Refined Detector MAY be generated only from a Seeding Incident — a DAP-confirmed true positive recorded in Organ 5. Unconfirmed, auto-labeled, or heuristically-scored detections SHALL NOT seed adaptation."

| Field | Content |
|---|---|
| Code path | `Kvasir::generate` → `self.ledger.confirmation(&seed.incident_id)`; refuses `UnconfirmedSeed` unless the ledger records the incident **and** its confirming DAP equals `seed.confirmed_by`. It does **not** trust the seed's own `confirmed_by`. |
| Test (fails if the gate is removed) | `test_oqgf_p_6_1_unconfirmed_seed_refused` (empty ledger → `UnconfirmedSeed`) and `test_oqgf_p_6_1_seed_confirmed_by_a_different_dap_refused` (recorded but wrong DAP → `UnconfirmedSeed`). If `generate` trusted the seed's claim, both would return `Ok`. |
| Verdict | **partial — honest limitation recorded.** The *structure* is a real gate (it consults an external authority, not the input's claim). But the authority is the `ConfirmedIncidentLedger` seam, whose **production binding to actual SAGA records is Phase 11** (querying Organ 5 is out of scope here; the only Phase-9 impl is a test double). So at Phase 9 the "recorded in Organ 5" clause is satisfied *against the seam*, not against real Organ-5 records. Recorded per Step-0 reading (c). |

## OQGF-P-6.2 — Selection on Independent Evidence

> "A Refined Detector SHALL be activated only if it demonstrates improved detection of the Seeding Incident's attack class against an Evaluation Corpus that is independent of the seeding sample. A candidate that improves only on the single seeding sample, or that improves detection at the cost of degraded coverage elsewhere in the corpus, SHALL be disqualified."

| Field | Content |
|---|---|
| Code path | `Kvasir::select`: (1) `corpus.version != current` → `StaleCorpus`; (2) recompute `Sha384(eval_corpus_digest_content(samples()))` vs the DAP-declared digest → `SubstitutedCorpus`, **before** measuring; (3) the seeding sample present in `samples()` → `Overfit`; (4) measure candidate vs incumbent — a benign/other-class regression → `CoverageRegression`, else zero improvement → `Overfit`, else `Ok(SelectionPass)`. |
| Test (fails if removed) | `_substituted_corpus_refused` (spies prove **nothing measured**), `_stale_corpus_refused`, `_corpus_containing_seed_refused`, `_overfit_refused`, `_coverage_regression_refused`; the positive path in `test_full_pipeline_...` proves a genuine improvement is selected. |
| Verdict | **partial — independence is NON-CONTAINMENT only (§13).** The disposed `SubstitutedCorpus`/`StaleCorpus` variants (R12) make the corpus-integrity refusals honest. But the independence check is **non-containment, not independence**: code verifies the corpus does not *contain* the seeding sample; it cannot verify the corpus was not *assembled* with the incident in view (a property of how the corpus was built, not its contents). Recorded per §13. The measurement gate is satisfied; enforcement is real and tested. |

## OQGF-P-6.3 — Tolerance-Gated Activation

> "No Refined Detector SHALL activate until it passes central-tolerance screening (OQGF-P-3) against the current Self Set. A refinement that improves detection but raises host harm above the declared bound SHALL be discarded regardless of its detection gains."

| Field | Content |
|---|---|
| Code path | `Kvasir::activate`: (a) `provenance.screen_result.version != current_self_set.version` → `FailsTolerance` (a stale screen does not establish current tolerance — version, not recency); (b) `Heimdall::screen(&candidate_spec, &current_self_set, now)` — **called, not reimplemented**; `FailsCentralTolerance` → `FailsTolerance`, applied *after* selection so there is no trade. |
| Test (fails if removed) | **`test_oqgf_p_6_3_raises_host_harm_refused`** — the candidate passes `select` (real gains) and `activate` **still** returns `FailsTolerance` because it fires on the Self Set. If Gate 3 were removed, activation would succeed despite the harm. Plus `_stale_screen_pass_refused`. |
| Verdict | **satisfied at Phase 9, with the host-harm measure a lower bound (§13).** The gate is real (HEIMDALL's screen) and the no-trade property is proven. "Raises host harm" is measured as *fires on the current Self Set* — a lower bound: it catches a candidate that fires on the declared known-good baseline, but the true host-harm rate counts only confirmed false positives (§13, inherited from HEIMDALL). Recorded honestly. |

## OQGF-P-6.4 — Detector Provenance

> "Every Refined Detector SHALL carry signed Detector Provenance — the Seeding Incident identifier, the Evaluation Corpus version, the self-tolerance screening result, and the approving DAP — recorded in Organ 5. A detector whose provenance cannot be reconstructed SHALL NOT be active."

| Field | Content |
|---|---|
| Code path | `activate` verifies `DualPublicKey::verify_dual(&canonical::provenance_signed_content(&provenance), &provenance.signature)`; the signed content covers the seeding id, corpus version, screen result (version + produced_at), and approver — every field except the signature (`canonical.rs`). `DetectorProvenance` is a by-value parameter, so activation without provenance is uncallable (I-9-style structural precondition). |
| Test (fails if removed) | `test_oqgf_p_6_6_activation_without_dap_approval_refused` (a provenance signed by a non-DAP key → `NeedsApproval`); the positive path activates a validly-signed provenance. If the signature check were removed, the impostor-signed provenance would not be rejected. |
| Verdict | **satisfied at the type/verification level; Organ-5 *recording* is Phase 11.** The provenance is verified (dual-family) and is a precondition of activation; recording it to Organ 5 is the orchestrator's job (Phase 11, out of scope). |

## OQGF-P-6.5 — Reversibility

> "Every activated Refined Detector SHALL be versioned and reversible. A rollback SHALL be a recorded event in Organ 5 carrying its justification and the acting DAP."

| Field | Content |
|---|---|
| Code path | `activate` returns `PriorGeneration { generation: self.prior_generation }` — the return type makes an activation that does not hand back what it replaced unrepresentable. |
| Test (fails if removed) | `test_full_pipeline_...` asserts `prior.generation == 1`. Reversibility is structural (the return type); it cannot be removed without changing the core trait. |
| Verdict | **satisfied at the type level; the rollback *event* and *trigger* are Phase 9-out-of-scope** (recording to Organ 5 is Phase 11; deciding *when* to revert is a DAP act, §6.12). |

## OQGF-P-6.6 — No Autonomous Activation above Baseline

> "At Enhanced assurance and above, activation of a Refined Detector SHALL require DAP approval. Autonomous generation and autonomous selection are permitted; autonomous activation is not."

| Field | Content |
|---|---|
| Code path | The DAP's dual-family signature over the provenance **is** the approval; `activate` returns `NeedsApproval` when it does not verify under the declared DAP key. (`generate` and `select` are autonomous — no approval — as permitted.) |
| Test (fails if removed) | `test_oqgf_p_6_6_activation_without_dap_approval_refused`. |
| Verdict | **satisfied.** Activation requires a valid DAP signature; a forged/absent one is `NeedsApproval` — honest (there is genuinely no valid approval), not a false claim. |

## OQGF-P-3 — Central Tolerance (consumed here)

> "Before activation, every Heuristic Response detector SHALL be screened against the declared Self Set and SHALL NOT be deployed if its host-harm rate against that baseline exceeds the declared bound."

| Field | Content |
|---|---|
| Code path | KVASIR **calls** `Heimdall::screen` (does not reimplement it — §6.12); HEIMDALL recomputes the Self Set corpus digest and runs the candidate, a single firing → `FailsCentralTolerance`. |
| Test | `test_oqgf_p_6_3_raises_host_harm_refused` (screen fires) and the positive path (screen passes). |
| Verdict | **satisfied by consumption** — the screening logic is HEIMDALL's (Phase 8, already conformant); KVASIR's contribution is to call it as Gate 3 and honor its verdict. |

## Structural invariants

- **I-5** — `brokkr-adapt` deps are `brokkr-core` + `brokkr-crypto` + `brokkr-sentinel` (governance/foundation); no `brokkr-tools`/`brokkr-cli`. `cargo tree` confirmed. **Satisfied.**
- **I-6** — KVASIR makes no model call; it reasons over committed types and calls HEIMDALL/crypto. **Satisfied.**
- **I-9** — `cargo tree` confirms **no `brokkr-reasoner`** dependency — the agent does not teach itself. And a `RefinedDetector` is `Heuristic` by construction (core's private `response_class`), proven by the `compile_fail` doctest and `test_i9_refined_detector_cannot_be_deterministic`. **Satisfied.**
- **I-13** — only `activate` takes `now` (per call); KVASIR holds no clock (four-pattern grep empty). `select`'s `produced_at` is a held audit stamp, not an evaluated clock — KVASIR has no expiry gate. **Satisfied.**
