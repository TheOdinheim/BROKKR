## 0. Scope of this revision

Additive. Adds `Skuld::verify_chain_public` (and `verify_root_public`): chain verification
using only declared **public roots of trust** (`DualPublicKey`), holding no private material —
the SKULD-side path SINDRI (Phase 4) will call with public keys resolved from OQGF-M-1
attestations. Consumes the `DualPublicKey` capability the Phase 2 revision
(`CONF-2026-07-17-P2-REV-R1`) added. **Builds no gate — SINDRI is Phase 4.** Every existing
Phase 3 test passes **unchanged**.

The refactor extracted the existing `verify_chain` walk into one private generic helper
(`verify_chain_with<V: DualVerify>`) over a **private** trait `DualVerify`, impl'd for both
`DualKeyPair` and `DualPublicKey` as one-line forwards to each type's inherent `verify_dual`.
Both public methods delegate to that single walk, so the keypair path and the public-key path
cannot drift. The preferred shared-walk path was taken; the duplicate-fallback was not needed
(the borrow checker did not fight, and behavior is preserved — §3).

## 2. The M-8 verdict, stated plainly (§7)

This revision closes the public-roots-of-trust half of OQGF-M-8 **on the chain-verifier side**:
`brokkr-intent` can now verify a chain with public keys only. It does **not** by itself wire an
OQGF-M-1 attestation to a resolved public key to this call — that is **SINDRI, Phase 4**. So the
**M-8 chain-verifier verdict in `CONF-2026-07-16-P3-R1` moves from `partial` toward satisfied but
is not fully closed**: the record-and-reconstruct half (Phase 3) and the public-key verify path
(this revision) are both done and tested; the attestation→public-key→verify wiring is Phase 4.
RISK-2026-0003 is updated accordingly — residual **further reduced, not closed**.
