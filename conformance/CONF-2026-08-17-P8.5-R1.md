## 1. AMD-001 — OQGF-M-5 (mutual authentication)

> *"Mutual authentication SHALL be required for every connection; one-sided TLS SHALL NOT satisfy this
> requirement."*

| Aspect | Implementation | Proof |
|---|---|---|
| One-sided TLS unrepresentable | `brokkr_core::genome::ModelEndpoint::client_cert` is a **required** field, not `Option`; an endpoint without a client certificate cannot be constructed, registered, or reached | structural (type-level); BIFRÖST adds **no** runtime check |
| The channel is measured, not assumed; effective = min(endpoint ceiling, channel strength) | `evaluate_context` delegates to HÚÐ's condition 8, which collapses the effective level from the **negotiated** group carried on `Destination::Reasoner` | **`test_oqgf_m_5_classical_group_collapses_to_public`**, `test_effective_is_min_not_endpoint`, `test_pqc_group_permits_declared_ceiling` |

**Verdict: SATISFIED.** mTLS is a type-level guarantee (no bearer-token shortcut is representable), and the
effective-ceiling collapse is enforced (a classical handshake denies above Public regardless of the
endpoint's ceiling). §6.10.1's gateway posture can **relocate** M-5 by a deployment choice (a gateway
forwarding to a public API), but that is a deployment decision about *what the crate is pointed at*, not a
change to what the crate enforces on the crossing it is given — so it does not alter this verdict.

## 2. AMD-007 — OQGF-I-9 (BCR), I-10 (egress, deterministic), I-12 (declared classification)

> **I-9:** *"Data … above the Public classification SHALL carry … a signed Boundary Custody Record …"* —
> **I-10:** *"… SHALL NOT cross … Absent a valid BCR authorizing the crossing, the Barrier SHALL deny it."*
> — **I-12:** content inference is Heuristic; *"a backstop to, never a replacement for, the deterministic
> enforcement of declared classification."*

| Req | Implementation | Proof | Verdict |
|---|---|---|---|
| **I-9** | above-Public crossings require a signed BCR, verified by HÚÐ (condition 4); BIFRÖST supplies the flow | `test_above_public_without_bcr_is_denied` (condition 2 `MissingCustodyRecord`); the Allow tests use a real signed BCR | **satisfied** (for the reasoner crossing) |
| **I-10** | the deterministic egress gate is HÚÐ's, delegated to — one gate, one logic; BIFRÖST re-implements no condition | the collapse + no-BCR denials above | **satisfied** (for the reasoner crossing) |
| **I-12** | `Context.classification` is **declared**; **no code reads `payload`** | grep (report §4) + `test_no_payload_inspection` (verdict independent of payload) | **confirmed structurally** |

**Verdict: I-9, I-10 satisfied for the reasoner crossing; I-12 confirmed.** The crossing is now the
enumerated controlled boundary the reasoner channel lacked in Rev 1.1. The residual — a *declared*
classification can be wrong, and no signature fixes a mis-declaration (§6.6/§13) — is named, not closed here.

## 3. AMD-007 — OQGF-I-13 (record the crossing) and I-14 (uncontrolled channels)

> **I-13:** *"Every Barrier decision … SHALL be recorded in Organ 5 …"* — **I-14:** enumerate and reduce
> reliance on Uncontrolled Channels.

- **I-13: PARTIAL.** BIFRÖST produces the crossing record's **material** (`CrossingRecord` — the negotiated
  group, derived strength, endpoint, effective ceiling, classification, verdict) as a **value**
  (`test_crossing_record_carries_negotiated_group`). **Recording to SAGA is Phase 11** — BIFRÖST does not
  depend on `brokkr-audit`. Not claimed satisfied.
- **I-14: not duplicated.** The Uncontrolled-Channel register is `brokkr-barrier`'s
  (`UncontrolledChannelRegister`, Phase 6); this phase does not re-implement it. BIFRÖST's contribution is
  the opposite — it makes the reasoner channel a **controlled** crossing (the Rev 1.1 lesson, §6.10), so the
  reasoner path is no longer an unenumerated uncontrolled channel. Traced.

## 4. AMD-009 — OQGF-P-11.1 (personal data, orthogonal, at every tier)

> *"… including where that tier is Public. A system that governs personal data only when it is also highly
> sensitive does not satisfy this requirement."*

**Verdict: SATISFIED for the crossing.** `Context.personal` (Rev 1.14) travels with the context and is
placed on the egress flow, so HÚÐ's condition 1 does **not** short-circuit a Public **personal** context to
Allow. `test_public_personal_context_does_not_short_circuit` proves a Public + personal + no-BCR context is
denied (`MissingCustodyRecord`) rather than cleared — the Rev 1.7 correction, at this boundary.
