## 1. AMD-001 — OQGF-M-14 (Intent Chain Freshness)

> *"Intent Provenance Chains SHALL carry a freshness nonce and an expiry. A chain whose expiry has
> passed SHALL NOT authorize action … Chain expiry SHALL NOT exceed the credential lifetime of the
> actor at the current hop."*

| Aspect | Implementation | Proof | Verdict |
|---|---|---|---|
| The current time is a **per-call** input to the gate, so freshness is evaluated against a present that cannot age with the gate (I-13) | `CostimulationGate::evaluate(&self, …, now: Timestamp)` and `authorize(&self, …, now: Timestamp)` — `now` is a parameter, never construction state | `test_i13_now_is_a_call_site_parameter`; `compile_fail,E0061` doctest (call without `now` does not compile) — standalone-verified `E0061` | call-site requirement **satisfied** |
| Each implementor actually **forwards** `now` to the chain-expiry check | — none in core — | — | **not provable in core** |

**Verdict: PARTIAL — and this is a backward move, recorded per §5.3.** Core now *requires* the
current time at every gate call site, which is the precondition for M-14 to be enforceable at all.
But core cannot prove an implementor forwards `now` rather than ignoring it and reading a held
clock — and that is exactly the defect that occurred: **SINDRI held its clock for four phases, so
M-14 was enforced against nothing.**

**Was Phase 4's `satisfied` on M-14 wrong at the time? Yes — stated plainly.** Phase 4 recorded
M-14 satisfied while SINDRI compared a chain expiry against `self.now` frozen at construction. A
gate alive for hours compared an aging expiry against an equally aging present: the arithmetic
worked, the check passed, and the requirement bound nothing. The earlier verdict is corrected
downward here; it is not preserved for consistency (§5.3: *"a conformance record whose verdicts
only ever improve is not being audited"*). Enforcement — each implementor threading `now` into its
freshness check — is the `brokkr-gate` revision and the Phase 8.5 rebuild, not this core revision.
M-14 stays **PARTIAL** until those land.

## 2. AMD-001 — OQGF-M-11 (Costimulation Gate)

> *"A privileged action SHALL require both a valid identity attestation … and a valid Intent
> Provenance Chain …"*

Unchanged in substance by this revision; the four conjuncts and their Phase-4 partial status
(Signals 1–2 enforced; action-in-scope and action-respects-invariants deferred under the
Deferred-Conjunct Deadline) are untouched. The only change is that `evaluate`/`authorize` now carry
`now`, which the freshness half of Signal 2 needs. **Verdict: PARTIAL, unchanged** — recorded here
only to note this revision did not advance or regress it beyond the M-14 correction above.

## 3. AMD-007 — OQGF-I-9 (Boundary Custody Record — the expiry clause)

> *"A BCR that is unsigned, malformed, or **expired** SHALL NOT authorize a crossing."*

The reasoner crossing's expiry check lives in HÚÐ's `Barrier::evaluate`, which already takes
`now`. This revision adds `now` to `ContextClearance::{evaluate_context, clear}` so BIFRÖST can
**reach** that check — without it, the clearance seam could not pass a time to the barrier and
would be forced into a wall-clock read (forbidden) or a held clock (I-13's defect). **Verdict:
satisfied for the seam shape** — the clearance now carries the time the barrier's expiry check
requires. Enforcement that BIFRÖST forwards it is the Phase 8.5 rebuild (same residual as M-14).

**A note this check is obligated to make (§5.3 / Task 3): a wrong doctest code is invisible to
`cargo test --doc`.** A probe confirmed rustdoc passes a `compile_fail` on *any* failure regardless
of the annotated code. Every code in this check was therefore verified by extracting the snippet
and compiling it with standalone `rustc`. That process found **one pre-existing wrong annotation**
— gate D1 emitted `E0451`, not the annotated `E0616` (a struct-literal private field is E0451; E0616
is field *access*) — the identical latent bug Rev 1.14 fixed in reasoner.rs, silently wrong in
gate.rs since Phase 1. Corrected. This is itself a small backward-then-forward correction to a
documentation claim, surfaced only because the codes were checked against the compiler rather than
against the annotation.

## 5. Result

**0 absent.** **PARTIAL (backward move, by design):** OQGF-M-14 at core — call sites now require
`now`; forwarding-enforcement is the gate rev + Phase 8.5 rebuild, and Phase 4's `satisfied` verdict
is corrected downward as wrong-at-the-time. **PARTIAL (unchanged):** OQGF-M-11. **Satisfied (seam
shape):** OQGF-I-9 expiry reachability from the clearance seam. **Holds:** I-1, I-12. **Newly
enumerable:** I-13 — core proves the call site supplies the time, not that an implementor forwards
it. No requirement is absent, so the build does not stop; the two intended downstream breakages
(`brokkr-gate`, `brokkr-bifrost`) are known consequences, not findings. This is a real check with
standalone-verified proofs, not an assertion.
