## OQGF-M-11 — The Costimulation Gate (AMD-001), as it constrains the reasoner

> "No actor SHALL be granted privileged action on the basis of identity attestation (Signal 1) alone. A privileged action SHALL require both a valid identity attestation per OQGF-M-1 and a valid Intent Provenance Chain per OQGF-M-8 (Signal 2). An actor presenting valid identity with absent, malformed, or invariant-violating intent provenance SHALL be placed in architectural anergy: all privileged action denied."

| Field | Content |
|---|---|
| Code path | MÍMIR produces a `Proposal { action, rationale, hop }` — an **untrusted** value that carries no authority. There is **no path** from a `Proposal` to an `AuthorizedAction` in `brokkr-reasoner`: the only minter of `AuthorizedAction` is `CostimulationGate::authorize` (sealed `mint`, `brokkr-core::gate`), and `brokkr-reasoner` neither implements that gate nor constructs an `AuthorizedAction`. The proposal must pass SINDRI (Phase 4) to become authorized. |
| Test (fails if removed) | `test_propose_with_cleared_context_produces_proposal` shows `propose` returns a `Proposal` (not an authorization); a grep confirms `brokkr-reasoner/src` contains no `AuthorizedAction` construction and no `authorize` call. If MÍMIR could mint authority, the type system would have to expose the sealed `mint` — which the `brokkr-core::gate` `compile_fail` doctests prove it does not. |
| Verdict | **satisfied** — MÍMIR is the untrusted proposer; the costimulation gate (SINDRI) is the only path from a proposal to an authorized action, and it is not in this crate. |

## OQGF-M-5 — Mutual authentication, as it bears on the endpoint

> "Mutual authentication SHALL be required for every connection; one-sided TLS SHALL NOT satisfy this requirement."

| Field | Content |
|---|---|
| Code path | The reasoner speaks only to a **registered** endpoint (§6.1 rule 3): `Mimir::new` refuses `ReasonerError::UnregisteredEndpoint` unless the endpoint is a registered member of the Model Endpoint Registry (the `RegisteredEndpoints` seam, backed by REGIN's signed `EndpointRegistry` in production). mTLS itself is a **type-level** guarantee upstream: `brokkr_core::genome::ModelEndpoint::client_cert` is a required field (not `Option`), so an endpoint that cannot present a client certificate is not representable and cannot be registered — a fact this crate consumes, not re-checks (BIFRÖST likewise adds no runtime mTLS check). |
| Test (fails if removed) | `test_unregistered_endpoint_refused` (an unregistered endpoint → `UnregisteredEndpoint`); the e2e test constructs the crossing against a registered endpoint. |
| Verdict | **satisfied at the reasoner's level** — the reasoner enforces endpoint registration at construction; the mutual-TLS unrepresentability of a certless endpoint is a committed-type guarantee (M-5, I-11) it relies on, owned by `brokkr-core::genome` / BIFRÖST, not re-implemented here. |

## Structural invariants

### I-6 — only `brokkr-reasoner` makes a model call, and only through BIFRÖST; no governance crate depends on it

`brokkr-reasoner` is the crate on the model-call side of the line; its (future) production backend makes the network call through BIFRÖST. Phase 10 builds no model call — the `ModelBackend` is a seam, and a `ClearedContext` (bifrost-cleared) is the only input to `propose`. **`cargo tree` evidence:** `brokkr-reasoner` → `brokkr-core`, `brokkr-bifrost`; and **no crate in the workspace depends on `brokkr-reasoner` or `brokkr-tools`** (grep over all `Cargo.toml` `[dependencies]` — the only matches are the I-5 *comments* in governance crates). **Satisfied.**

### I-12 — an ungoverned context cannot reach a model

`Reasoner::propose` takes `&ClearedContext`, which has no public constructor (minted only by BIFRÖST's provided `clear`). **Code path:** `Mimir::propose` reads `ctx.get().payload` and passes only the text to the backend. **Tests:** the `compile_fail,E0308` doctest in `brokkr-core::reasoner` (a raw `Context` cannot be passed — still passing) + `test_i12_propose_requires_cleared_context` + `test_end_to_end_real_bifrost_clears_then_proposes` (the real barrier mints the `ClearedContext`). **Satisfied.**

### I-5 — the untrusted side does not invert the dependency line

Both crates are on the untrusted side. `brokkr-tools` → `brokkr-core` only; `brokkr-reasoner` → `brokkr-core` + `brokkr-bifrost`. **No governance crate depends on either** (verified). Neither reaches `brokkr-tools`/`brokkr-cli` improperly, and `brokkr-tools` does not depend on `brokkr-reasoner` (nor the reverse). **Satisfied.**

### I-1 (as it bears on brokkr-tools) — a tool cannot self-authorize

A `ToolExecutor` receives an `AuthorizedAction`; it constructs none (the mint is sealed). **Test:** `test_tool_does_not_reauthorize` + the `compile_fail` doctest in `brokkr-tools/lib.rs` (forging an `AuthorizedAction` does not compile). **Satisfied.**
