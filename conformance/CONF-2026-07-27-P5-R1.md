## 2. The predicate-5 finding (the stop)

BROKKR-ARCH §6.2 predicate 5 — "a `ToolEntry` names a capability the intent vocabulary does not
recognize" — requires a committed set of recognized capabilities to check against. **There is
none:** `Capability` is an open `String` (`intent.rs:16`), no register enumerates valid
capabilities, and the only derivable set (the union of `ToolEntry.required_capabilities`) makes the
check vacuous — a predicate that can never fire, which §6.2's own predicate 6 (line 434) condemns as
"worse than absent." §6.2 posits an "intent vocabulary" the committed types do not commit. Building
predicate 5 would require inventing that vocabulary source, which §4 and the phase instruction
forbid. Filed as **GAP-2026-07-27-001**; the build stops.

**Backward verdict movement (v1.6 §5.3).** No prior record claimed predicate 5 satisfied, so nothing
moves backward here. OQGF-G-4's *architecture-level* six-predicate rendering is recorded **partial
at the type surface** (five of six predicates computable); the *corpus* G-4 (present/signed/free of
disallowed algorithms) remains buildable. This is recorded as a §6.2-vs-committed-types disagreement,
not a corpus requirement going unmet.
