## OQGF-P-12.5 — Independent Termination (F-36)

> "a mechanism to pause or terminate the system that is architecturally independent of the agent … The termination path SHALL NOT depend on the agent's cooperation … or on the model's willingness to comply."

| Field | Content |
|---|---|
| Code path | `brokkr-cli` `KillSwitch` (new): `Arc<AtomicBool>` behind a type that exposes only `kill()` / `is_killed()` / `handle()` — **no `unset`**. `Orchestrator::kill_switch()` hands out a latch handle; `run_hop` reads `self.kill_switch.is_killed()` before every gate. **F-36 fix:** activation is now irreversible for the session — a compromised thread that set the latch cannot be overridden by another clearing it, because there is no clear. The type also fixes the memory ordering (`Release` on set, `Acquire` on read), so a caller cannot weaken it to `Relaxed`. |
| Test | `redteam_16::fix_kill_switch_is_a_latch` (killed stays killed; a second handle sees the latch; no clear API). Fails against the pre-fix `Arc<AtomicBool>` (which exposed `store(false, ..)`). |
| Verdict | **strengthened / satisfied.** The path still does not traverse the model (unchanged), and termination is now a one-way latch. Residual (unchanged, accepted): the check is **pre-hop**, not a mid-hop abort (F-37), so latency is bounded by the longest in-flight tool call — a bound, not a cooperation dependency. |

## OQGF-P-12.4 — Deterministic Default-Deny Egress (F-35, F-34) — **PARTIAL**

> "all outbound network traffic SHALL be denied unless the destination, protocol, and port are listed in a signed egress manifest."

| Field | Content |
|---|---|
| Code path | `brokkr-cli` `check_egress` + `normalize_destination` (new). **F-35 fix:** both the incoming host and each manifest rule's destination are normalized (lowercase, trim, fold `127.0.0.1`/`::1` → `localhost`) before comparison, so the same endpoint spelled differently cannot bypass the manifest, nor be falsely denied. Deliberately conservative — no DNS resolution (the deterministic gate must not depend on a lookup). |
| Test | `redteam_16::fix_egress_ip_hostname_equivalence` (127.0.0.1 now admitted against a `localhost` rule — fails pre-fix), `fix_egress_still_denies_unknown` (normalization does not broaden). Default-deny on an empty manifest still holds (`empty_manifest_denies_all_network`). |
| Verdict | **PARTIAL.** Destination matching is enforced and now representation-robust. **Port and protocol remain unenforceable (F-34), and this is recorded, not glossed:** `EgressRule` declares `{ destination, port, protocol }` as P-12.4 requires, but `Destination::Network` (a `brokkr-core::barrier` type) carries only `{ host, channel }` — no port, no protocol — so `check_egress` matches host alone. Full satisfaction requires adding port/protocol to `Destination::Network` and a full-tuple match; that is a governing-type change (it touches HÚÐ), out of scope for a hardening pass, and is referred to the DAP. |

## OQGF-P-12.1 / P-12.2 — Dual-Axis Determination / Envelope Validity (F-32, F-33, Fix 3) — **PARTIAL**

> "A system whose capabilities are not inventoried, not signed, and not assessed for tier determination does not satisfy this requirement."

| Field | Content |
|---|---|
| Code path | `brokkr-core` `CapabilityEnvelope::validate` (unchanged: `TierMismatch` / `TierTooLow`) + `permissive()` now `debug_assert!(validate().is_ok())` (**Fix 3**), so the library-provided default is guaranteed valid in any debug/test run. |
| Test | `redteam_16::fix_permissive_validates`; the `debug_assert` itself fires in every debug workspace run. |
| Verdict | **PARTIAL.** The type-level determination is correct and the default is now a guaranteed-valid envelope. **But the orchestrator boundary does not enforce validation:** `with_envelope` installs a caller-supplied envelope **without calling `validate()`** (F-32), and `new()` defaults to a *permissive* envelope with no egress manifest (F-33, fail-open — unlike `guards = Guards::production()`). BROKKR's shipped composition supplies a signed, valid envelope, but the boundary permits an invalid or absent one. Closing this is a design decision the DAP prescribed only in part (Fix 3, the default); a validating install path or a deny-safe default is referred to the DAP. |

## Prime directive §2 — the model is not in the trust path (reaffirmed, strengthened)

| Field | Content |
|---|---|
