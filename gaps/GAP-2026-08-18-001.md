# GAP-2026-08-18-001 — A third held clock: brokkr-sentinel (EIR + HEIMDALL) violates I-13

**Filed:** 18 August 2026
**Phase:** 8.5 rebuild (`brokkr-bifrost` adopts the I-13 surface) — discovered incidentally
**Filed by:** the builder, during Task 4's mandated workspace held-clock grep
**Status:** OPEN — reported to the DAP; **not fixed** (brokkr-sentinel is out of this revision's scope)
**Does it block this revision?** **No** for the `brokkr-bifrost` deliverable (which is complete and
green). **Yes** for **RISK-2026-0006's closure** — its closure condition is an empty workspace
held-clock grep, and the grep is not empty.

---

## What was found

RISK-2026-0006's closure condition is *"the workspace grep for a held clock returns empty."* Running
that grep across **all** crates (not just the two the risk named) surfaced a **third** held clock —
in `brokkr-sentinel`, in **two** engines:

**EIR (`brokkr-sentinel/src/eir.rs`)** — the resolution engine, which governs de-escalation, **the
one act in BROKKR that lowers a defence** (OQGF-P-8.5).
- `struct EirState { now: Timestamp, … }` (eir.rs:54) — the current time is **construction state**,
  set at `Eir::new(dap_public, now)` (eir.rs:77) and mutated out-of-band by `set_now` (eir.rs:92).
- `ResolutionEngine::resolve` reads the held clock — `let now = st.now;` (eir.rs:232) — and checks
  the **resolution-decision expiry** against it: `if now.0 > d.expiry.0 { return Err(Expired) }`
  (eir.rs:242). `resolve(&self, d: ResolutionDecision)` does **not** take `now` as a parameter.

**HEIMDALL (`brokkr-sentinel/src/heimdall.rs`)** — the tolerance controller (OQGF-P-4).
- `struct HeimdallState { now: Timestamp, … }` (heimdall.rs:42), set at construction and by
  `set_now` (heimdall.rs:108).
- Grant application checks the **tolerance-grant expiry** against the held clock:
  `if self.state().now.0 > grant.expiry.0 { … Expired … }` (heimdall.rs:268).

Both fields carry the in-code justification *"injected … never a wall-clock read … determinism"* —
which is **the exact rationalization Rev 1.15 rejected** when it added I-13. Satisfying "never a
wall-clock read" with a value held at construction is precisely the trap: a gate alive across calls
compares an aging expiry against an aging (or stale) held present, and the freshness check passes
while enforcing nothing.

## Why this is an I-13 violation, not a false positive

CLAUDE.md §3 I-13 (v1.7): *"A gate that evaluates an expiry takes `now` as a parameter of the
**evaluating call**, never as construction state. … The current time is the one input that is wrong
the instant after it is read, and holding it makes a gate progressively more permissive the longer
it lives."*

EIR evaluates the resolution-decision expiry (Rev 1.12/1.13's replay/latency defence on P-8.5) and
HEIMDALL evaluates the tolerance-grant expiry (P-4) — both are *"a gate that evaluates an expiry"* —
and both read a **held** `now` rather than a call parameter. This is the same defect class as
SINDRI (RISK-2026-0006) and the original BIFRÖST, in a third crate. The EIR instance is arguably the
most consequential of the three: a held clock that makes an **expiry stale** on a **de-escalation
decision** weakens the freshness guarantee on the one operation that *lowers* a defence — the
operation Rev 1.12/1.13 hardened specifically so a captured stand-down cannot be replayed later
"when the escalation it clears is real and current."

## Why it survived until now

`brokkr-sentinel` was built at **Phase 8 (12–14 Aug)**, **before I-13 existed** (ARCH Rev 1.15,
CLAUDE.md v1.7, 17 Aug). The SINDRI and BIFRÖST corrections were scoped to the crates whose builds
**broke** on the core trait's new `now` parameter; sentinel's `now` was never a trait parameter, so
it never broke the build and was never reviewed against I-13. The mandated grep is what surfaced it —
which is the value of making an invariant grep-checkable rather than prose (the Rev 1.15 rationale
for I-13 itself).

## Why the builder did not fix it

The scope lock for this revision is explicit: *"Touch brokkr-bifrost ONLY … Do NOT modify …
brokkr-sentinel …"*. Fixing sentinel here would violate the scope lock, and the fix is a design
change to two engines (thread `now` through `resolve`, `may_resolve`, `scan_chronic`, and the
grant-application path as a call parameter; remove the held field and `set_now`) that warrants its
own reviewed revision — exactly as SINDRI and BIFRÖST each got. Silently working around it, or
quietly closing RISK-2026-0006 despite a non-empty grep, are both forbidden (§4, §10).

## Recommendation (for DAP decision)

1. **Place a `brokkr-sentinel` I-13 revision**, the third in the series after SINDRI and BIFRÖST:
   `resolve`/`may_resolve`/`scan_chronic` and the tolerance-grant-application path take `now:
   Timestamp` as a call parameter; the `now` field and `set_now` are removed from `EirState` and
   `HeimdallState`; add the two-verdict test to each (one instance, two `now` values, two verdicts —
   impossible against a held clock), mirroring the SINDRI/BIFRÖST analogues. **This unblocks nothing
   for the builder** — it is more work, named because it is correct, not because it is convenient.
2. **Expand RISK-2026-0006's scope** (or open a sibling risk) to record that the held-clock class is
   **workspace-wide**, not a two-crate matter, and that its closure condition (empty workspace grep)
   is met only when **all three** crates are corrected. This revision closes the BIFRÖST half; the
   sentinel half is now the outstanding remainder.
3. **The deeper residual stands and is untreated:** the sentinel instances, like SINDRI's, sat in
   committed, DAP-ratified code — and (for EIR/HEIMDALL) under phase conformance checks that recorded
   P-4/P-8.5 satisfied. Those checks used fixed-`now` fixtures that could not have caught a held
   clock, the same test-agrees-with-the-defect shape RISK-2026-0006 names. That is a process residual
   (a "does this test have a way to fail?" discipline), not closed by any of the three code fixes.

## Disposition of RISK-2026-0006 in this revision

**Not closed.** The BIFRÖST half is corrected (see the phase report and `CONF-2026-08-18-P8.5-R2`);
the SINDRI half was corrected on 18 Aug (`PHASE-4-REV-2026-08-18-R1`). But the workspace grep is
**not empty** because of this finding, so the risk's own closure condition is unmet. RISK-2026-0006's
UPDATE records the BIFRÖST closure and points here for the remaining sentinel half.

— End of GAP-2026-08-18-001.
