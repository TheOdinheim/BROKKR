## What the new tests prove

| Test | Requirement | Establishes |
|---|---|---|
| `test_verify_chain_public_accepts_valid_multihop` | M-8 (public roots of trust) | A verifier holding ONLY exported public keys (`DualKeyPair::public_key_bytes` → `DualPublicKey::from_public_bytes`) verifies a valid 2-hop chain — no private material reaches verification |
| `test_verify_chain_public_and_keypair_paths_agree` | M-8 / behavior preservation | For one chain, `verify_chain` (keypairs) and `verify_chain_public` (the SAME keys' public halves) both return `Ok` — the two paths agree, confirming the shared walk is equivalent |
| `test_verify_chain_public_rejects_tampered_entry` | M-9 (attenuation re-check) | Broadening hop-1's `emitted_scope` on a reconstructed chain is rejected (`WouldBroaden` or `EntrySignatureInvalid`) — broadening is not merely detectable, it does not verify |
| `test_verify_chain_public_rejects_wrong_key` | M-8 | A different keypair's public half for hop 0 → `EntrySignatureInvalid { hop: 0 }` — verification is keyed to the correct public root of trust |
| `test_verify_chain_public_expired` | M-14 (freshness) | `now` (20_000) > `expiry` (10_000) → `Attenuation(Expired)`, refused before the walk — same freshness gate, one code path |
| `test_verify_chain_public_hop_key_missing` | fail-closed | Fewer hop publics than hops → `HopKeyMissing { hop: 1 }` — a missing verifying key fails closed, never silently skipped |
